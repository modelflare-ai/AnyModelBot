## 一、业务背景与要解决的问题

v0.1.34 已上线定时规则、模板、新手引导三块能力。产品体验中发现一批逻辑、功能、交互和文案问题，本次只修这些已知问题，不加新功能。

| 优先级 | 编号 | 问题 | 影响 |
| :--- | :--- | :--- | :--- |
| P0 | 1 | Modelflare 额度预占失败（Unable to reserve quota）没有被认成余额不足 | 新用户第一句话就失败，只看到「任务没有完成」，没有充值和切换模型，只能反复重试 |
| P1 | 2 | 电脑操作权限卡只缺一项时仍用复数标题 | 中文「需要你开启 1 个权限」生硬，英文出现「1 permissions needed」 |
| P1 | 3 | 电脑操作权限卡没有独立的「需要重新打开」状态 | 开了屏幕录制仍不生效时，用户找不到下一步 |
| P1 | 4 | 模板在体验额度期内不降档，推荐理由不对 | 新用户不知道为什么没给推荐档位 |
| P2 | 5 | 撤销后的文案不一致 | 规则卡、飞书卡片、渠道回复三处说法不同 |
| P2 | 6 | 在别的会话里改删规则的范围不完整 | 主人在部分会话里找不到这个机器人的全部规则 |
| P2 | 7 | 在规则卡上切换开关后「撤销」消失 | 第一次运行前就不能撤销 |
| P2 | 8 | 频繁运行提示建议的频率仍会触发提示 | 提示让用户改成「每小时」，改完提示还在 |
| P2 | 9 | 模板初始记忆会让上手清单「让它记住你」直接完成 | 用户没学会「记住」就被判完成 |
| P2 | 10 | 模板示例句和渠道说明 | 预览页和添加后输入框里的说法不对 |
| P2 | 11 | 新手引导文案与定稿文案不一致 | 示例、说明、画图引导说法不对 |
| P2 | 12 | 侧栏「+」菜单里「模板」排在「新建机器人」和「新建群聊」中间 | 菜单顺序不对，新建类操作被打断 |
| P3 | 13 | 「定时」页说明、空状态、关闭状态文案 | 说法不统一 |
| P3 | 14 | 新规则对话框文案 | 说法不统一 |
| P3 | 15 | 「结果发到」缺渠道说明 | 用户不知道还能发到聊天工具 |
| P3 | 16 | 模板自带规则的启用确认框缺说明 | 用户不知道为什么要先选发到哪里 |

**文案总则**：本文只给中文和英文。日文、韩文、俄文、西班牙文、葡萄牙文等其他已有语言，须在同一次开发中按确认后的中文含义同步更新。英文里带数量的文案，数量为 1 时用单数，2 及以上用复数，分开写。中文文案提到聊天渠道时写微信、飞书；英文写 Slack、Telegram、Discord。

## 二、产品逻辑

### 任务报错的归类顺序

报错先归类，再决定主提示和按钮。按下表从上往下判断，命中第一条即停：

| 顺序 | 类别 | 判断条件 | 主提示和按钮 |
| :--- | :--- | :--- | :--- |
| 1 | 余额不足 | 状态码 402；或报错里有额度、余额不足的说法，包括 Modelflare 的「Unable to reserve quota」（额度预占失败），不论状态码是 403 还是其他 | 余额类主提示 + 「充值 ↗」「切换模型…」「重试」 |
| 2 | 凭据失效 | 状态码 401，或 Key、令牌无效或过期 | 凭据类提示 + 修改 Key |
| 3 | 模型不可用 | 模型不存在、不可用、不支持工具 | 模型类提示 + 「切换模型…」 |
| 4 | 限流 | 状态码 429，或请求过于频繁 | 限流提示 + 「重试」 |
| 5 | 网络 | 连不上、超时 | 网络提示 + 「重试」 |
| 6 | 其他 403 | 状态码 403 且不属于以上各类 | 「服务拒绝了这次请求（403）」 |
| 7 | 其他 | 以上都不是 | 「这个任务没有完成。」 |

状态码从报错正文里任意位置识别，不受前面加的说明影响，例如「⚠️ 代理执行失败：403 {…}」「⚠️ Agent run failed: 403 {…}」和其他语言的同类前缀，都要识别出 403。

### 模板的推荐档位

| 情况 | 预选模型 | 推荐理由 |
| :--- | :--- | :--- |
| 不在体验额度期内 | 模板声明档位里满足能力要求的模型 | 推荐：模型智能「{档位}」 |
| 体验额度期内，模板档位不高于全局默认所在档位 | 模板声明档位里满足能力要求的模型 | 推荐：模型智能「{档位}」 |
| 体验额度期内，模板档位高于全局默认所在档位 | 降到全局默认所在档位，在这一档里选满足能力要求的模型 | 当前体验额度下先用「{实际档位}」，这个模板通常更适合「{原推荐档位}」。 |
| 降档后这一档没有满足能力要求的模型 | 跟随全局默认 | 推荐档位没有满足能力要求的模型，先跟随全局默认。 |

档位名只用 低 / 中 / 高。体验额度期指新账号仍在使用初始体验额度的阶段。

## 三、需求详情

### 1. 额度预占失败识别为余额不足（P0）

**当前表现**：

- Modelflare 返回 403 和「Unable to reserve quota」时，报错被当成「其他 403」，主提示是「服务拒绝了这次请求（403）…」。
- 报错前面带「⚠️ 代理执行失败：」时，连 403 也识别不出，主提示变成「这个任务没有完成。」。
- 两种情况都没有「充值 ↗」和「切换模型…」，只有「重试」，重试也解决不了。

**要求表现**：

1. 按第二节「任务报错的归类顺序」，额度预占失败归为余额不足，不论状态码是多少。
2. 状态码识别不受报错前缀影响；状态码和 request id 显示在折叠的「错误详情」里。
3. 用 Modelflare 时：主提示、说明、「充值 ↗」「切换模型…」「重试」都显示，充值直达当前账号的 Modelflare 充值页。
4. 用自己的 API Key 时：显示对应厂商的余额提示，不引导去 Modelflare 充值。
5. 侧栏会话预览只显示「失败：余额不足」，不显示原始报文。
6. 已有的其他类别判断不受影响。

**文案**：

| 位置 | 中文 | English |
| :--- | :--- | :--- |
| 主提示（Modelflare） | 余额不足，暂时无法继续此任务。 | Your balance is too low to continue this task right now. |
| 说明（Modelflare） | 充值后可以重新发送；也可以换一个模型试试，但不保证一定能完成。 | Top up and send it again, or try another model (that may still not be enough). |
| 按钮 | 充值 ↗ · 切换模型… · 重试 | Top up ↗ · Switch model… · Retry |
| 主提示（自己的 Key） | {name} 账户的额度不足，暂时无法继续此任务。 | Your {name} account doesn't have enough credit to continue this task. |
| 说明（自己的 Key） | 这是你自己的 {name} API Key，请到 {name} 的控制台检查余额或额度，然后重新发送。 | This uses your own {name} API key. Check the balance or quota in the {name} console, then send it again. |
| 侧栏预览 | 失败：余额不足 | Failed: low balance |

**验收**：

- 「⚠️ 代理执行失败：403 {"error":{"message":"Modelflare: Unable to reserve quota…"}}」显示余额类主提示，带「充值 ↗」「切换模型…」「重试」，错误详情里显示状态码 403。
- 「403 {"error":{"message":"Unable to reserve quota"}}」和英文前缀「⚠️ Agent run failed: …」同样处理。
- 不含额度说法的普通 403 仍显示「服务拒绝了这次请求（403）」。
- 侧栏预览只显示「失败：余额不足」。
- 用自己的 Key 时不出现 Modelflare 充值按钮。

### 2. 电脑操作权限卡：单数标题（P1）

**当前表现**：只缺一项权限时，标题是「需要你开启 1 个权限」，英文是「1 permissions needed」（图 1 左上）。

**要求表现**：

1. 只缺一项时用单数标题，缺两项及以上时用带数量的标题。
2. 缺的项数变化时（比如两项开了一项），标题随之切换。

**文案**：

| 位置 | 中文 | English |
| :--- | :--- | :--- |
| 标题（缺一项） | 需要你开启一个权限 | One permission needed |
| 标题（缺两项及以上） | 需要你开启 {count} 个权限 | {count} permissions needed |

**验收**：只缺辅助功能时标题为「需要你开启一个权限 / One permission needed」；辅助功能和屏幕录制都缺时为「需要你开启 2 个权限 / 2 permissions needed」；开了其中一项后切换为单数标题。

### 3. 电脑操作权限卡：需要重新打开（P1）

**当前表现**：屏幕录制在系统设置里已开启、但要重新打开应用才生效时，卡片标题不变，主按钮仍是「去开启」；重启说明和「重新打开」按钮只在折叠的「打不开？手动开启」里（图 1 左下）。

**要求表现**：

1. 已请求屏幕录制、但还没生效时，整张卡片切换为「需要重新打开」状态（图 1 右下）：
   - 标题「还差一步：重新打开 AnyModelBot」。
   - 说明一句，告诉用户重新打开后才生效、聊天和草稿保留。
   - 唯一主按钮「重新打开」，旁边「稍后」；不再显示「去开启」和「打不开？手动开启」。
2. 点「重新打开」前保存所有草稿和待继续的请求；重新打开后检测通过，就自动接着做刚才的事。
3. 重新打开后仍未生效时，卡片回到待授权状态，可以再次「去开启」。

**文案**：

| 位置 | 中文 | English |
| :--- | :--- | :--- |
| 标题 | 还差一步：重新打开 AnyModelBot | One more step: reopen AnyModelBot |
| 说明 | 重新打开后屏幕录制才会生效，聊天和草稿都会保留。 | Screen Recording takes effect after reopening. Your chats and drafts are kept. |
| 按钮 | 重新打开 · 稍后 | Reopen · Later |

**验收**：

- 在系统设置开启屏幕录制、回到应用仍未生效时，卡片标题变为「还差一步：重新打开 AnyModelBot」，主按钮为「重新打开」，不需要展开任何折叠区。
- 重新打开后草稿还在，并自动接着做。

### 4. 模板：体验额度期内降档（P1）

**当前表现**：体验额度期内的新用户打开任意模板预览，模型一律跟随全局默认，推荐理由是「上手期间先跟随全局默认，你也可以自己选择。」，看不到这个模板原本适合哪一档、现在用的是哪一档。

**要求表现**：

1. 按第二节「模板的推荐档位」预选模型并写推荐理由。
2. 模板档位不高于全局默认所在档位时，正常推荐，不出现降档说明。
3. 降档时下方不再重复显示「这个模板通常更适合…」。
4. 用户手动选过模型后，不再自动改回。

**文案**：

| 位置 | 中文 | English |
| :--- | :--- | :--- |
| 推荐理由（正常） | 推荐：模型智能「{level}」 | Recommended: {level} intelligence |
| 推荐理由（降档） | 当前体验额度下先用「{actualTier}」，这个模板通常更适合「{originalTier}」。 | On the trial quota this bot will use {actualTier} first. This template usually works better with {originalTier}. |
| 降档后无可用模型 | 推荐档位没有满足能力要求的模型，先跟随全局默认。 | No model in the recommended tier meets the requirements, so it follows the global default for now. |

**验收**：

- 体验额度期内、全局默认在「低」档时，打开「资料研究员」（高档）预选低档里满足能力要求的模型，推荐理由为「当前体验额度下先用「低」，这个模板通常更适合「高」。」。
- 同样条件下打开「写作助手」（低档），推荐理由为「推荐：模型智能「低」」。
- 不在体验额度期内时，不出现降档说明。

### 5. 撤销后的文案统一（P2）

**当前表现**：

- 对话里的规则卡撤销后写「已撤销 · 这条规则不会再运行。可恢复到 {time}。」，标题少了「规则 ·」。
- 飞书卡片撤销后用的是渠道回复那句「10 分钟内回复「恢复」可以找回」。
- 微信等渠道撤销后写「不会再运行」。

**要求表现**：

1. 规则卡撤销后，标题保持「规则 · {name}」并整体划线，正文用下表「已撤销」。
2. 飞书卡片点「撤销」后原地更新为「飞书撤销后」那句，按钮换成「恢复」，不再提示回复文字。
3. 微信等渠道回复「撤销」后，用「渠道撤销后」那句。

**文案**：

| 位置 | 中文 | English |
| :--- | :--- | :--- |
| 规则卡已撤销 | 已撤销 · 这条规则已删除，不会再运行。10 分钟内可以恢复（到 {time}）。 | Undone · This rule was deleted and won't run. You can restore it until {time}. |
| 飞书撤销后 | 已撤销 · {name} 不会再运行。10 分钟内可以恢复。 | Undone · {name} won't run. You can restore it within 10 minutes. |
| 渠道撤销后 | 已撤销「{name}」，不会再发了。10 分钟内回复「恢复」可以找回。 | Undid "{name}". It won't be sent again. Reply "restore" within 10 minutes to get it back. |

**验收**：三处撤销后的说法与上表一致；规则卡撤销后标题仍有「规则 ·」。

### 6. 在别的会话里改删规则（P2）

**当前表现**：在聊天渠道里，只有主人和机器人的私聊能找到这个机器人的全部规则；主人在其他会话里说「把早报改到 9 点」，只能找到这个会话里建的规则。

**要求表现**：

1. 主人在任何会话里（桌面对话、应用内群聊、微信、飞书私聊）说要改或删某条规则，都能找到这个机器人的全部规则。
2. 重名时机器人先问是哪一条。
3. 不是主人的人（群里其他成员、渠道里的其他联系人）只能改删在自己会话里建的规则。

**验收**：在 A 会话建的规则，主人在 B 会话里能改；群里其他成员改不了别人建的规则。

### 7. 切换开关后「撤销」仍保留（P2）

**当前表现**：刚建好的规则，在规则卡、右侧面板或「定时」页上切换一次开关，规则卡上的「撤销」就消失，即使还没运行过。

**要求表现**：

1. 「撤销」的有效期只看两件事：到这条规则第一次运行前，最长 24 小时，两者取先到的。
2. 只切换开关、改发到哪里，不影响「撤销」是否还在。
3. 机器人改了规则内容（名称、原话、时间）时，按「规则已修改」处理，「撤销」退回修改前的版本。
4. 撤销后 10 分钟内「恢复」，规则回到撤销前的样子，包括开关状态。

**验收**：建好规则后在卡片上关掉再打开，「撤销」仍在；第一次运行后或超过 24 小时后「撤销」消失。

### 8. 频繁运行提示的建议频率（P2）

**当前表现**：检查类规则每月超过 300 次时提示运行很频繁，提示建议「改成每小时」；每小时一个月约 720 次，改完仍会提示。

**要求表现**：

1. 「大约每月 {N} 次」按接下来 30 天的计划次数计算。
2. 检查类每月超过 300 次时，橙色提示运行很频繁；提醒类不提示。
3. 提示里建议的频率都必须低于 300 次：每 3 小时约 240 次，每天约 30 次。
4. 英文次数为 1 时用单数。

**文案**：

| 位置 | 中文 | English |
| :--- | :--- | :--- |
| 频率（1 次） | 大约每月 1 次 | About 1 run a month |
| 频率（2 次及以上） | 大约每月 {count} 次 | About {count} runs a month |
| 高频提示 | 运行很频繁，会比较费额度。想省一点可以改成每 3 小时或每天。 | This runs often and will use more of your quota. To save, run it every 3 hours or once a day. |

**验收**：

| 频率 | 每月次数 | 高频提示 |
| :--- | :--- | :--- |
| 每 15 分钟 | 约 2880 | 出现 |
| 每小时 | 约 720 | 出现 |
| 每 2 小时 | 约 360 | 出现 |
| 每 3 小时 | 约 240 | 不出现 |
| 每天 | 约 30 | 不出现 |

### 9. 上手清单「让它记住你」只认用户自己记住的内容（P2）

**当前表现**：从模板页添加带初始记忆的机器人（如写作助手、日程秘书），会写入初始记忆笔记；上手清单「让它记住你」只看有没有记忆，可能因此直接显示完成。

**要求表现**：

1. 「让它记住你」只在用户在对话里让机器人记住一条内容、并保存成功后完成。
2. 模板写入的初始记忆不算完成。
3. 已经完成这一步的用户，进度不变。

**验收**：新用户从模板页添加写作助手（长期记忆开着），「让它记住你」仍未完成；在对话里发「记住：回答尽量简短，结论放在最前面。」保存成功后完成。

### 10. 模板示例句和渠道说明（P2）

**当前表现**：多个模板的英文示例句和渠道说明与下表不一致；资料研究员、编程搭档、群聊日报助手、客服助手的中文示例句，以及群聊日报助手的中文渠道说明，也被换掉了。

**要求表现**：模板卡片、预览页和添加后填进输入框的示例句，以及预览页的渠道说明，统一用下表。示例句添加后只填进输入框，不自动发送。

| 模板 | 项 | 中文 | English |
