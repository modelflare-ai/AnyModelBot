# スキルのインポートと管理

[简体中文](./skills.md) | [繁體中文（台灣）](./skills_zh-TW.md) | [English](./skills_en.md) | 日本語 | [한국어](./skills_ko.md) | [Русский](./skills_ru.md) | [Español](./skills_es.md) | [Português (Brasil)](./skills_pt.md) | [Türkçe](./skills_tr.md)

AnyModelBot 0.1.24 から、週報作成、文書処理、資料整理などの作業手順を ZIP 形式のスキルとしてボットに追加できます。

## インポート

1. 対象ボットの設定を開き、「スキル → ZIP をインポート」を選びます。
2. ローカルの ZIP を選び、名前、説明、ファイル数を確認します。説明を展開すると全文を読めます。
3. 「スキルを追加」をクリックします。関連する作業でボットが必要に応じて読み込みます。

ZIP ごとにスキルは 1 つです。`SKILL.md` は ZIP のルートにも、外側のフォルダー内にも置けます。`scripts/`、`references/`、`assets/` などの付属ファイルも保持します。インポート時に GitHub へ接続したり、インストール用スクリプトを自動実行したりすることはありません。

`SKILL.md` には YAML のヘッダーと指示本文が必要です。

```markdown
---
name: weekly-report
description: ユーザーの作業メモから週報を作成する。
---

完了した作業、問題点、翌週の予定を整理し、指定された形式でまとめる。
```

名前は英小文字、数字、単独のハイフンで構成し、最大 64 文字です。ZIP は最大 20 MB、展開後は最大 64 MB・2000 項目、`SKILL.md` は最大 256 KB です。インポートできるスキルはボットごとに 100 個までです。複数の `SKILL.md` がある場合はスキルごとに ZIP を作成してください。

## スキルライブラリや GitHub からインストール

- 「アプリとスキル」の「スキル」タブで、スキルライブラリを用途別や作者別に見られます。ボット設定のスキル欄にも「スキルライブラリを見る」があります。「インストール指示をコピー」を押し、その文を任意のボットに送ります。
- スキルの GitHub リンク（リポジトリ、`/tree/<ブランチ>/<パス>` のフォルダ、`SKILL.md` ファイル）をボットに送って「これを入れて」と伝えることもできます。
- ボットがスキルの名前、説明、提供元、ライセンス、ファイル数を読み取り、確認カードを出します。「インストール」を押すまで書き込まれず、そのボットにだけインストールされます。チャットチャンネルではカードの番号を返信して確認し、Feishu のカードにはボタンがあります。インストールできるのはオーナーだけです。
- インストールしたスキルは一覧で提供元「GitHub · リポジトリ」と表示され、「表示」ではリポジトリ、パス、ブランチ、インストール時のコミット、インストール日時を確認できます。

## このパソコンから取り込む（マイスキルライブラリ）

パソコン上のほかのツール（Claude Code、Codex、Cursor、CodeBuddy など）にインストール済みのスキルを、まとめてマイスキルライブラリに取り込み、ボットでオンにできます。

- 入口：アバターメニュー ›「マイスキルライブラリ」›「このパソコンから取り込む…」、またはボット設定 ›「スキル」›「このパソコンから取り込む…」。探せるのはライブラリがあるパソコンのデスクトップアプリだけです。ブラウザやリモートでは ZIP か GitHub のリンクを使ってください。
- 自動で探すのは次の 6 か所です：`~/.codebuddy/skills/`、`~/.qwenworkcn/skills/`、`~/.agents/skills/`、`~/.claude/skills/`、`~/.cursor/skills/`、`~/.codex/skills/`。フォルダと `SKILL.md` のファイル名だけを見て、本文や記憶、アカウントは読みません。ほかの場所（`~/.workbuddy/skills/`、Doubao の `.user_skills/`、特定のプロジェクトなど）は「フォルダを選択…」で選びます。プロジェクトでは `.claude/skills/` などの既知の場所だけを確認します。ホームフォルダ、ディスクのルート、アプリデータ全体は丸ごと探しません。
- 候補は最初どれも選ばれていません。選んで「次へ」を押したときだけ読み取ります。確認画面では、取り込めます／すでにあります（内容が完全に同じ。状態はそのまま）／同じ名前で内容が異なります（既定はスキップ。「別に保存」を選ぶと呼び出し名はそのまま、表示名に番号が付きます）／非対応（理由付き）を項目ごとに示します。スクリプトを含むものには「スクリプトを含みます。取り込み時には実行しません」、依存関係があるものには「依存関係は未確認です」と表示します。
- ボットから開いた場合は「取り込み後に{ボット}で使う」が最初からオン、ライブラリから開いた場合はライブラリへの追加だけです。取り込み後、追加・オン・スキップ・失敗の件数をまとめて表示します。オンにできなかった場合（同じ名前のスキルがオン、容量がいっぱい）も、追加した内容はライブラリに残ります。
- 取り込まないもの：個人的なファイルの可能性があるもの（`.env`、`id_rsa`、`credentials.json`、`memory.md` など）、選んだ場所の外を指すリンク、このアプリで同じように保てない制限（`allowed-tools`、`hooks` など）、プラットフォームのパス変数（`${CLAUDE_PLUGIN_ROOT}` など）、参照先ファイルがないスキル。`disable-model-invocation` と `user-invocable` はそのまま保持し、Codex の `allow_implicit_invocation: false` は `disable-model-invocation: true` として書き込みます。
- 取り込みはコピーです。取り込み元は変わらず、同期もしません。ライブラリには各スキルが 1 つだけあり、ボットはオン・オフだけを持ちます。ボット設定の「ライブラリから追加…」やスイッチは、そのボットにだけ影響します。ボットに入れた ZIP / GitHub のスキルや自分で保存したスキルもライブラリに並びます。
- マイスキルライブラリでスキルを開くと、内容と使っているボットを確認できます。取り込んだスキルをどのボットもオンにしていなければ、「⋯」›「ライブラリから削除」でライブラリのコピーだけを削除できます。

## 使用・置き換え・削除

- スキルは追加したボットだけに適用されます。同じボットはアプリとチャットチャンネルで共通のスキルを使います（マイスキルは下記参照）。
- 一覧から説明の表示、有効化、無効化、削除ができます。変更はボットが待機状態になってから反映されます。
- インポートが成功すると、いつから使えるか（次のメッセージから、現在のタスクの後、または読み込み後）と「こう言ってみましょう」の例が表示され、「入力欄に入れる」（このボットの会話を開きます）か「コピー」を選べます。ボタンを押すか閉じるまで表示されたままです。
- 同名のスキルを再インポートし、確認後に「スキルを置き換え」を選ぶと更新できます。有効・無効の状態は維持されます。
- 削除しても、ワークスペースに作成済みの成果物は残ります。
- `media`、`computer-use`、`amb-app` などの組み込みスキルやカタログ Bot 付属のスキルは上書きできません。

実行にはボットの既存の権限を使います。Python、追加ソフトウェア、アカウント接続などが必要なスキルでは、その環境を用意してください。他クライアント専用のツールに依存する場合は調整が必要です。形式に対応していても、付属ツールがすべてインストールされているとは限りません。

## 会話で使う

- メッセージ入力欄の左にある「+」›「スキルとアプリ」を開くと、このボットがいま使えるスキルとアプリが表示されます。項目を選ぶと「{名前}を使って…」が入力欄に入るので、続きを書いて送信します。使うかどうかはボットが判断します。
- 設定のスキル一覧では、名前の横に「有効」「次のメッセージから有効」「読み込み中」のいずれかが表示され、その下に「こう言ってみましょう」の例があります。例をクリックすると、このボットの入力欄に入ります。
- ボットがスキルやアプリを使っている間は、返信の上の処理経過に「スキルを使用中 · {名前}」と表示され、アプリはツールごとに1行ずつ「{アプリ} · {ツール} を使用中」と表示されます（アプリが表示名を用意していればそれを使います）。返信が終わると「使用：…」の1行にまとまり、開くと全ステップを確認できます。
- 「どんなスキルがある？」「どんなアプリがある？」と聞くと、いま使えるものを、そのまま送れる例と一緒に挙げます。
- `SKILL.md` に `disable-model-invocation: true` と書かれたスキルは、ボットが自分からは使わず、「スキルとアプリ」にも表示されません。メッセージに `/スキル名` と書くと使われます。

## やったことをスキルとして保存

ボットと一緒にうまくいったやり方は「マイスキル」に保存して、次回そのまま使ったり、定期実行に設定したりできます。

- 始め方：入力欄の「+」メニューで「スキルとして保存…」を選ぶか、`/skill` を送るか、「スキルとして保存」と話しかけます。一部だけ残したいときは「手順 3 をスキルとして保存」と伝えます。ボットが返信中なら、この返信が終わってからまとめます。
- ボットは「スキルをまとめています…」と表示したあと、下書きカードを出します：タイトルとファイル名、使うとき、手順、あなたが直したこと（チェックを外せます）、使うアプリとスキル、「こう言ってみてください」。「編集」でスキルファイルを直接編集でき、完了するともう一度確認します。「保存」を押すまでファイルは書き込まれません。カードは 30 分で期限切れになります。
- シークレット（API キー、トークン、パスワード、確認コード、Cookie、身分証番号）はスキルに書き込まれず、編集で戻しても保存できません。電話番号、メールアドレス、人名、グループ名、ワークスペース外のファイルパスは強調表示され、既定は「使うたびに確認」です。プレースホルダーとして保存され、使う前に毎回確認します。「残す」を選ぶと原文を書き込みます。
- タスクが終わっていなくても保存できます。下書きにどこで止まったかを書き、「未検証」として保存します。このスキルで一度最後までできると表示が消えます。
- タイトルが同じとき、またはボットが同じ作業だと判断したときは、変更箇所の数を示し、「更新」か「新しいスキルとして保存」を選べます。更新すると前のバージョンが残り、「管理」から戻せます。
- マイスキルは全体で 1 つのリストで、このパソコンにだけ保存され、最大 100 個です。各ボットにインポートしたスキルとは別に数えます。最初は保存したボットでだけオンになり、ほかのボットではスキル一覧のスイッチをオンにすると使えます。保存できるのはオーナーだけで、WeChat や Feishu のグループからは始められません。
- スキル一覧のマイスキルの行には「表示」と「管理」があります。「管理」では ZIP のエクスポート（このスキル自身のファイルだけ。残した個人情報があれば先に確認）、前のバージョンへの復元、削除ができます。エクスポートした ZIP は別のパソコンでローカル ZIP スキルとしてインポートできます。
- 保存後に「定期実行に設定」を押すと、ボットが時刻を確認して「作業を依頼」ルールを作り、毎回スキルの最新版で実行します。パソコン操作、画像・動画の生成、バックグラウンドタスクが必要なスキルと、未検証のスキルは定期実行に設定できません。スキルが削除されたとき、そのボットでオフにされたとき、更新や復元のあとで先に答えが必要な項目や定期実行ではできない手順が増えたとき、未検証になったときは、ルールが一時停止し、「スケジュール」の「対応が必要」に表示されます。
- スキルが 10 個を超えると、一覧の上に検索欄と「すべて / マイスキル / GitHub / ローカル ZIP / オフ」の絞り込みが出ます。処理の経過に出るスキル名から詳細を開けます。

## 保存先

展開したパッケージはデータディレクトリ内の `skills/<ボット ID>/` に保存し、有効なものを実行用の `dsh/<ボット ID>/skills/` にコピーします。インポート先は使用中の AnyModelBot インスタンスだけです。サーバー運用の場合、ファイルはそのサーバーに保存されます。有効なスキルの名前と説明、使用時に読み込んだ本文や参考資料は、選択したモデルに送るコンテキストになります。[データとプライバシー](./privacy_ja.md)も参照してください。

マイスキルはデータディレクトリの `my-skills/` に保存され、オンにしているボットごとに実行時に `dsh/<ボット ID>/skills/` へコピーされます。

このパソコンから取り込んだスキルはデータディレクトリの `skill-library/` に保存され、オンにしているボットごとに実行時に `dsh/<ボット ID>/skills/` へコピーされます。ボットを削除しても、そのボットに入れていたスキルはマイスキルライブラリに残ります。
