# AnyModelBot 设计库

界面样式的唯一来源。无构建步骤：原生 CSS（`@layer` + 自定义属性）+ Preact/htm 组件。

- 样例页：本机服务的 `/amb/static/design/index.html`。token 表直接从 `tokens/*.css` 解析，不会和代码脱节；支持浅色/深色和双主题对照，也能模拟"减少动态效果"；设置 › 外观里的偏好（字体大小、字体、动画）在样例页里同样生效。
- 守卫测试：`test/design-system.unit.test.ts`。`npm test` 时检查规范有没有被破坏（规则见文末）。

## 目录

```
ui/design/
  index.css              入口：声明层顺序并按层引入下面所有文件
  tokens/
    primitives.css       L1 原始值：品牌/状态色板，间距、字号、圆角、控件高度、层级等尺度
    semantic.css         L2 语义 token：按用途命名、按主题取值（浅色 + 深色）；另有与主题无关的间距角色、字体与用户偏好
    motion.css           动效 token：时长、缓动、位移量、--motion 开关
  base/
    reset.css            重置、焦点环、可选中规则
    motion.css           关键帧库 + .anim-* 工具类 + 减少动态效果
    typography.css       文字角色 .t-*（在 utilities 层）
    utilities.css        .stack .cluster .grow .truncate .tone-* .sr-only
  components/            一个组件一个文件：icon glass button field badge list seg tabs switch stops popover model-family sheet splitter toast notice feedback avatar
  motion.js              ms("--dur-base")、usePresence()、useListPresence()、reducedMotion()
  index.html / gallery.* 样例页
ui/css/                  页面样式（shell / chat / settings / guide），放在 app 层
ui/components/ui.js      组件的 JS 写法：Icon Button IconButton Notice Skeleton Seg Switch Stops Menu MenuButton Sheet …
```

## 层叠顺序

```css
@layer tokens, base, components, app, utilities;
```

后面的层总是赢，和选择器权重无关：

- 页面样式（`ui/css/*.css`，整个文件包在 `@layer app { … }` 里）可以直接覆盖组件，不用拼权重。
- 工具类和文字角色在最后，加上就生效。
- 新的页面样式文件也要包进 `@layer app`，否则它会是"无层"样式，压过所有层。

## Token

**分两层。** 原始值（`--lime-500`、`--space-3`、`--r-md`）描述"有什么"；语义 token（`--primary`、`--line`、`--muted`）描述"用在哪"。

| 类别 | 规则 |
|---|---|
| 颜色 | 页面和组件**只用语义色**。原始色板只在 `semantic.css` 里引用。新颜色先加语义 token（两个主题都要给值），再用。 |
| 字号 | 9 级 `--fs-2xs … --fs-4xl`（12 / 13 / 14 / 14 / 15 / 16 / 20 / 24 / 28，不用半像素，控件和界面正文同为 14，对话正文 16），都乘以 `--fs-scale`（设置 › 外观 › 字体大小）。新界面优先用文字角色 `.t-*`；跟着文字走的长度（比如输入框行高 `--composer-line`）也乘 `--fs-scale`。 |
| 字重与字距 | `--fw-semibold` 只给标题：页面、分组、对话框、顶栏与面板标题、提问卡的问题、正文里的标题、12px 小标签。名称一类（机器人名、文件名、模板名、账户名、信息面板的行）用 `--fw-medium`；设置页的行名称用常规字重，层次交给分组标题和 `--muted` 的说明。大标题用 `--tracking-tighter`（-.015em）、二级标题 `--tracking-tight`（-.01em）——中文字形本来就满，不要收得更紧；行高用 `--lh-*`，不写 1.45 这类散值。 |
| 字体 | 只用 `--font` / `--code`。它们默认是各平台的系统字体 `--font-system` / `--code-system`，用户可以换成衬线 `--font-serif` 或自定义字体（见「用户偏好」）。 |
| 圆角 | 页面和组件**只用圆角角色**（见「形状」）：面 `--r-pane` 24 / `--r-card-lg` 20 / `--r-card` 16，面里的东西 `--r-row` 16 / `--r-item` 14 / `--r-item-sm` 10（同心算出来），控件 `--r-ctl`（胶囊）/ `--r-field` 12，图标底 `--r-tile` 12 / `--r-tile-sm` 8，内容 `--r-bubble` 24 / `--r-composer` 28 / `--r-mark` 6，圆形 `50%`。primitives 的 `--r-xs … --r-4xl`、`--r-full` 和兼容名 `--r-well` 只给 token 文件、样例页和目录 Bot 的界面（守卫测试会拦）。 |
| 间距 | 4 的倍数 `--space-1 … --space-16`，另有 `-0-5 / -1-5 / -2-5 / -3-5` 半步。页面和组件先用按用途命名的间距角色（见下文「间距」）。写死的像素只允许 0、≤1px 的细线，以及同一行带 `/* 微调：… */` 注释的光学微调。 |
| 控件高度 | `--ctl-xs … --ctl-2xl`（24 / 28 / 32 / 36 / 40 / 48）。默认按钮、顶栏图标按钮 32，输入框、建议胶囊、标签页、发送钮 36。 |
| 细线 | `--hairline`：一个物理像素（普通屏 1px，高分屏 .5px）。浮层的细边都用它——写死 `.5px` 在 1x 屏上会被抗锯齿成一道若有若无的虚影。 |
| 层次 | `--well` / `--well-hover` / `--well-press`（内容里的一组，只有这一层）；`--fill-field` / `--fill-field-hover`（输入框的填充）；`--line-2`（表头下沿）；`--red-wash` / `--amber-wash`（提示行的淡底）。规则见「容器与层次」。 |
| 投影 | 分三档，只给浮在内容上的东西，都很淡：`--shadow-float`（输入框、回到底部、提示胶囊）、`--shadow-pop`（菜单、引导卡片、抽屉）、`--shadow-modal`（对话框、命令面板）。`--shadow-pane` 是 `none`（面板靠底色和窗口分开）。`--seg-edge` 是分段 thumb、开关圆钮的一点点影子。见「容器与层次」。 |
| 层级 | 只用 `--z-*`；同一窗格内的浮动件用 `calc(var(--z-float) ± 1)`。 |
| 焦点 | 输入框：填充深一级 + 一圈和填充同色的淡光晕（错误时 `--ring-danger`）；其他控件：全局 `:focus-visible` 2px 描边、外移 2px，装在会裁切的容器里时用 `--focus-offset` 往里收。 |

现有语义色名（`--bg --card --pill --line --fg --muted --accent …`）沿用 magpie 的叫法，分组见 `semantic.css` 里的 `/* —— 组 —— */` 注释。

## 形状与尺度

用户 2026-11-09 要求：字整体大一点，顶部的标签页、按钮这些偏圆润、更饱满，整体更有设计感、更像面向个人用户的应用（参考 Grok）。落到 token 上是四条：

- **字大一档**：控件和界面正文 14、对话正文 16、页面大标题 28（原来 13 / 15 / 24）。层次靠字重和颜色，不靠把小字压得更小。
- **能点的控件一律是胶囊**（`--r-ctl` = `--r-full`）：按钮、分段、标签页、下拉、建议胶囊、侧栏搜索框；方的图标按钮就是圆。面越大越圆（面板 24、大卡片 20、小卡片 16），面里的行和项同心（16 / 14 / 10），输入框 12，对话输入框最圆（28）。完整的规则见「形状」。
- **控件更饱满**：高度整体高一档（见上表），图标使用 Heroicons Outline，常规线宽 1.5，开关 40 × 24。
- **留白更足**：面板内容边距 20、内容列两侧至少 32、页面上边距 48、分组之间 40；设置行 64 高。数值都在下面「间距」的角色里，不在页面里另写。

标签页（`.tabs`，`components/tabs.css`）是顶栏、面板里切换一整块内容的那排胶囊：胶囊轨道 + 一颗静止的白色胶囊；设置里的取值仍用 `Seg`（thumb 跟着值滑动）。

## 间距

页面和组件先用**间距角色**（`semantic.css` 里与主题无关的 `:root` 块，样例页「间距与尺寸」里有表），没有合适的角色时才直接用 `--space-*`。**一个角色只用一个值**：同一种用途不要这里 10、那里 12、别处 14。

| 角色 | token | 值 | 用在哪 |
|---|---|---|---|
| 面板间隙 | `--pane-gap` | 8 | 主区、信息面板离窗口边缘；弹出层离窗口边缘 |
| 面板内容边距 | `--pane-px` | 20 | 信息面板的标题与行文字、对话顶栏的头像 |
| 图标按钮内缩 | `--ib-inset` | 8 | 顶栏图标按钮（32）里 16 的图标离按钮边的距离；对齐按图标外沿算时用它 |
| 顶栏边距 | `--head-px` | 12（= `--pane-px` − `--ib-inset`） | 对话、信息面板、新建页的顶栏到首尾按钮 |
| 工具栏间隙 | `--bar-gap` | 4 | 一排图标按钮：顶栏、输入框工具栏、消息操作 |
| 侧栏边距 | `--side-inset` | 8 | 侧栏的行、搜索框、顶部按钮、账户离侧栏边缘 |
| 侧栏行内边距 | `--side-row-px` | 12（= `--pane-item-px`） | 机器人行、设置导航、账户、返回、搜索框 |
| 侧栏行间隙 | `--side-row-gap` | 2 | 相邻两行 |
| 内容列边距 | `--page-gutter` | 32（窗口窄于 1000px 时 20） | 对话列、输入框、设置页、新建页、引导页两侧至少留这么多 |
| 页面上 / 下边距 | `--page-top` / `--page-bottom` | 48 / 64 | 设置页、新建页、引导页 |
| 分组间距 | `--section-gap` / `--section-gap-sm` | 40 / 24 | 页面里 / 窄面板里分组标题的上方 |
| 标题到内容 | `--heading-gap` | 12 | 页面分组标题的下方 |
| 大标题到第一组 | `--title-gap` | 24 | 设置页、发现页的页面标题下方 |
| 块与块 | `--stack-gap` | 12 | 卡片、表单、展开编辑区里上下排的块（对话框大一档：16） |
| 卡片内边距 | `--card-pad` | 20 | 提问 / 审批卡、引导页卡片、侧栏空状态、模板卡 |
| 对话框内边距 | `--sheet-pad` | 24 | `.sheet` |
| 按钮组间隙 | `--ctl-gap` | 8 | 对话框、卡片、展开编辑区里的一组操作 |
| 浮层离窗口 | `--float-inset` | 16 | 提示胶囊、命令面板、对话框 |
| 弹出层离锚点 | `--pop-offset` | 8 | `usePopPosition`（JS 读 token 的像素值，不写死） |

**对齐的线**，改间距时守住：

- **顶部中线**：侧栏顶部先让出 `--pane-gap` 再放 `--head-h`，顶部三个按钮（收起侧栏 | 搜索 | 新建）和主区、信息面板的顶栏按钮在同一条水平线上。收起靠左，搜索和新建靠右，按钮间统一用 `--bar-gap`；收起图标较浅（`--muted`），搜索为轻量图标按钮，只有新建使用常驻 `--pill` 底色。定时放在下面的固定导航中，以图标加文字呈现。侧栏收起后，同样三个按钮按原顺序浮在主区左上角（`.side-rail`）；对话类页面的顶栏从按钮右边开始，设置类页面的大标题落到顶栏那一条下面。顶栏里的图标按钮一律 32（`--ctl-md`）：16 的图标四周各 8（`--ib-inset`），算对齐时按图标的外沿算。
- **窗口标题栏**：桌面版没有系统标题栏，侧栏顶部这一行就是标题栏。左上角看平台：macOS 让给红绿灯（`--titlebar-inset`），不放 Logo（应用名在菜单栏里）；Windows（`:root.win-app`）在收起钮后面放应用图标（`--brand-mark` 20）+「AnyModelBot」，整块是拖动区。Windows 的右上角是系统画的最小化 / 最大化 / 关闭，和这一行一样高、贴住窗口右上角。最右边的面板（信息面板开着时是它，抽屉也是；关着时是主区）贴住这个角：上、右不留 `--pane-gap`，右边两个角是直角，按钮落在它的顶栏上，底下没有一截环境光，也没有面板的边、圆角和投影；底边照旧离窗口下沿 `--pane-gap`。这块面板的顶栏往上长出 `--pane-gap`，内容仍在顶部中线上，右边多让出按钮的宽度 `--caption-w`，这时两种顶栏不再左右对称。信息面板开合时，主区的角和顶栏跟着列宽一起滑。样例页「Windows 标题栏」里有模拟的窗口，右上角的按钮是替身。信息面板自己的关闭钮在 Windows 上不放，免得和窗口的关闭钮挨成两个 ×。浏览器里和 Linux 桌面版用的是系统 / 浏览器的标题栏，这些都不出现。
- **底边**：侧栏的账户行离窗口下沿 `--pane-gap`，和主区、信息面板的下沿对齐；"已保存"浮在账户行上方一个 `--side-inset`，左边和侧栏的行对齐。
- **更新入口**：仅在有新版本或正在更新时，账户行右侧显示 32px 的带底色图标按钮；点击直接下载，准备好后点击重启更新。下载中显示进度状态，任务运行期间不允许重启，详情仍可在设置 › 关于查看。

- **侧栏竖线**：行、搜索框、账户的边离侧栏边缘 `--side-inset`；头像、导航图标、搜索图标、返回箭头、收起钮的图标左沿都在 `--side-inset + --side-row-px`（20）；搜索框的文字、"返回应用"和设置导航的文字在同一条竖线上（搜索图标 14 + 间隙 12 = 导航图标 16 + 间隙 10）。新建按钮的图标右沿落在行文字的右边线上（同样离侧栏右边 20），和机器人行的时间右对齐。机器人列表的右边距用外边距：滚动条贴着行的右边，不落进侧栏和主区之间的空隙（那里是分隔条）。
- **空隙**：侧栏与主区、主区与信息面板之间都是 `--pane-gap`；分隔条就放在空隙正中（见「分隔条」）。
- **面板竖线**：信息面板的标题、分组标题、行文字、展开编辑区、待审批说明都在 `--pane-px`（20）；对话顶栏是 `--head-px` + 按钮自带的 `--ib-inset`，头像也落在 20。两种顶栏都左右对称：最右边那个图标的外沿同样离面板右边 20。
- **输入框**：加号钮和发送钮都是 36 的圆、离输入框的边 `--composer-pad`（10），加号的图标正好落在文字的起点（20）上；模型、权限胶囊矮一档（32），不和两端的圆钮抢。输入框的圆角是 `--r-composer`（28）。
- **居中列**：对话列和输入框同宽 `min(--col-w, 100% − 2 × --page-gutter)`，设置页、新建页、引导页两侧也至少 `--page-gutter`。对话列的下边距和"回到底部"的位置由输入框高度 `--composer-h` 算出来。
- **弹出层**：列表离边缘 `--pop-pad`（= `--list-pad` 6），项再缩进 `--item-px`（10），于是项的文字、分组名、分隔线、搜索图标、空状态都在离边缘 16 的线上（见「内边距」）。
- **行**：默认行上下 8，"标题 + 说明"两行的行和一行的行一样高（56；设置页 64）；`.row.compact` 只是矮一些，左右和默认行一样；`.row-edit` 的左右也和行一样，输入框和上面那行的文字对齐。

## 形状

用户 2026-11-09 要求：按钮和整体再圆润一点；圆角规范起来、不混用——大卡片、小卡片、卡片里各用多少，组件怎么用，哪里用圆形、方形、胶囊的图标。

**四种形状，各管一类东西**（先看是什么，再定形状；形状定了，大小只影响圆角的数值）：

| 形状 | 写法 | 用在 | 不用在 |
|---|---|---|---|
| 圆 | `50%`（方的元素用 `--r-ctl` 也是圆） | 只有图标、能点的按钮：顶栏 / 工具栏的图标按钮、输入框的加号和发送、回到底部、复制、关闭、返回；身份：头像、账户首字母；点：状态点、提示蓝点；序号：引导和连接步骤的数字 | 带字的东西（带字就是胶囊）；代表"一种东西"的图标（那是方块） |
| 胶囊 | `--r-ctl` | 带字的控件和标签：按钮、文字按钮、下拉、分段和标签页、建议 / 示例胶囊、模型 / 权限 / 任务胶囊、提示胶囊、计数徽标、完成标记；侧栏和弹出层的搜索框；开关、滑块、进度条、拖动落点线这类圆头的条 | 可以打字的输入框（那是方的）；撑满一行的行（那是面里的行） |
| 圆角方块 | `--r-tile`（36–48 见方，12）/ `--r-tile-sm`（20–28 见方，8）；应用图标按 30% | 代表"一种东西"的图标底：模板卡的图标、提问卡的选项字母、色块、应用图标。约 1/4–1/3 边长，比面的圆角更"方"，一眼看出不是按钮 | 能点的单个图标（那是圆） |
| 圆角矩形（面） | 按层级，见下表 | 装东西的面、可以打字的框、行和项 | — |

**面越大越圆，面里的东西同心：**

| 层级 | 角色 | 值 | 用在 |
|---|---|---|---|
| 窗口面板 | `--r-pane` | 24 | 主区、信息面板、对话框、命令面板、搜索弹窗、引导页卡片 |
| 大卡片 | `--r-card-lg` | 20 | 一组内容或一块独立的卡：设置分组、提问 / 审批卡、引导清单卡、模板卡、待处理、发现封面、弹出层与菜单 |
| 小卡片 | `--r-card` | 16 | 内容里的一块东西：代码块、行内提示、文件卡、图片、日志、处理过程、主题缩略图、示例、二维码、技能说明 |
| 面板里的行 | `--r-row` = 面板 − `--pane-gap` | 16 | 侧栏的导航和机器人行、账户、信息面板的行和展开区、搜索结果、命令面板的项 |
| 大卡片里的项 | `--r-item` = 大卡片 − `--list-pad` | 14 | 菜单项、提问卡的选项、引导步骤、选择列表、建群的成员、选角色 |
| 小卡片里的项 | `--r-item-sm` = 小卡片 − `--list-pad` | 10 | 处理过程的步骤、文件卡里的可点区 |
| 输入框 | `--r-field` | 12 | 单行、多行输入框。小于最矮的输入框（32）高度的一半，看得出是"可以打字的框"，不会被当成胶囊按钮 |
| 气泡 | `--r-bubble` | 24 | 用户消息、会话记录；一行时就是胶囊 |
| 对话输入框 | `--r-composer` | 28 | 界面里最大的一块圆角 |
| 文字里的记号 | `--r-mark` | 6 | 行内代码、搜索高亮、骨架条、图表的柱头、只在键盘焦点时才看得见的文字链接 |

- **只用角色，不挑数值。** 页面和组件不直接写 `--r-sm`、`--r-full` 这些 primitives；新东西先判断它是哪种形状、在哪一层，再取对应的角色。组件对外的圆角变量（`--btn-r`、`--pop-r`、`--act-r` …）也从角色取值。守卫测试会拦原始圆角 token 和随手写的百分比；插画、应用图标这种按自己轮廓画的，在同一行写 `/* 形状：理由 */`。
- **同心是算出来的。** 面里贴着角的东西 = 外层 − 间距（上表"行""项"）。换了外层（比如命令面板是面板一级），就在那个面上把 `--pop-pad`、`--item-px` 换成面板的值，项的圆角自然变成 `--r-row`，不要另写一个数。
- **兼容名。** `--r-well` 只留给目录 Bot 的界面（`bots/*/ui`），等于小卡片；Bot 套件 `ui/botkit/kit.css` 已经改用角色。

## 内边距

用户 2026-11-09 要求：从设计原理上把上下左右和各组件的内边距规范起来。原来组件和页面里有 116 种 padding 写法，多半是直接挑一个 `--space-*`；现在按下面五条推出来，值都是 `semantic.css`「内边距」组里的角色。

**1. 内边距由"它是第几层容器"决定，越往外层越大。** 同一层的东西用同一个值，换层才换值：

| 层 | 是什么 | 左右（内容线） | 上下 | 圆角 |
|---|---|---|---|---|
| 轨道 | 分段、标签页、开关、档位滑块：装着一个控件的槽 | (轨道高 − 28) / 2：分段 2、标签页 4 | 同左 | 胶囊 |
| 控件 | 按钮、下拉、胶囊、标签、输入框：单行、定高 | 跟着高度：24 → 8，28 → 12，32 → 14，36 → 16，40 → 20（`--ctl-px-*`，约 0.45 × 高，字停在圆头结束的地方）；输入框一律 12（= `--r-field`） | 不写：定高、居中 | `--r-ctl` / `--r-field` |
| 项 | 菜单项、处理过程的步骤、提问卡的选项、选择列表 | `--item-px` 10 | 定高 36（`--ctl-lg`），主角列表 40 | `--r-item` 14 = 大卡片 20 − `--list-pad`；小卡片里 `--r-item-sm` 10 |
| 列表 | 装着一列项的容器：弹出层、命令面板、处理过程、账户菜单 | `--list-pad` 6（+ 项的 10 = 16） | 同左 | 外层的圆角 |
| 组 | `--well`：设置分组、代码块、行内提示、文件、待处理、日志 | `--group-pad` 16 | 行定高；多行内容 16 | 设置分组、待处理是大卡片 `--r-card-lg` 20；代码块、提示、文件、日志是小卡片 `--r-card` 16 |
| 卡片 | 独立的一块：提问 / 审批卡、引导卡片、模板卡、引导页卡片、侧栏空状态 | `--card-pad` 20 | 20 | `--r-card-lg` 20；引导页卡片 `--r-pane` |
| 面板 | 主区顶栏、信息面板、侧栏、搜索弹窗、命令面板 | `--pane-px` 20：离边 `--pane-gap` 8 + 行的 `--pane-item-px` 12 | 顶栏 56 | `--r-pane` 24，里面的行 `--r-row` = 24 − 8 |
| 对话框 | `.sheet` | `--sheet-pad` 24 | 24 | `--r-pane` |
| 页面 | 居中的内容列 | `--page-gutter` 32 | 上 48、下 64 | — |

**2. 容器的内边距 + 项的内边距 = 内容线。** 一个容器里所有的字（标题、行、说明、空状态、搜索框）都从同一条竖线开始：组和弹出层是 16，面板和侧栏是 20，卡片 20，对话框 24。项有悬停底时，底往外伸出项的内边距，字仍在内容线上：弹出层是 6 + 10，侧栏和信息面板是 8 + 12；提问卡的选项、选择列表、建群的成员、引导清单的步骤排在卡片或对话框里时，列表用 `margin: 0 calc(-1 * var(--item-px))` 往外伸。

**3. 圆角同心。** 贴着外层的角时，内层圆角 = 外层圆角 − 两者的间距：`--r-item` = `--r-card-lg` − `--list-pad`（20 − 6），`--r-row` = `--r-pane` − `--pane-gap`（24 − 8），分段和标签页的项都是胶囊。内边距不小于圆角的一半（组 16 / 20、面板 20 / 24、输入框 12 / 12），字不落进弯里。

**4. 上下：单行的东西定高、居中，多行的块四周一样。** 控件、项、行都给高度（`--ctl-*`、`--row-h`），不靠上下内边距撑高——字号调大时只是字变大，控件不变高（文字按钮 `.text` 也是 28 定高）。"标题 + 说明"两行的行和一行的行一样高。多行的块四周用同一个值（组 16、卡片 20、对话框 24）。行尾有小控件时，控件离上、右、下一样远：行内提示是 10（28 的按钮放在 48 高的一行里），代码块的复制钮 4（36 高的条里放 28 的按钮）。

**5. 间隙：里面的比外面的小。** 图标和字 6–8 < 一排图标按钮 4 / 一组按钮 8（`--bar-gap` / `--ctl-gap`）< 块与块 12（`--stack-gap`；对话框 16）、分组标题到内容 12（`--heading-gap`）< 大标题到第一组 24（`--title-gap`）< 分组与分组 40（`--section-gap`，窄面板 24）。

**光学修正**只有一种写成了角色：行尾是 12 的下拉箭头时那一侧少 `--ctl-trail`（4）——下拉、模型胶囊、任务胶囊都是 `0 calc(var(--ctl-px-md) - var(--ctl-trail)) 0 var(--ctl-px-md)`。其他微调照旧写在同一行的 `/* 微调：… */` 里。

**已知的例外**（有意的，不要"修"）：对话顶栏的机器人名胶囊左边是 `--ib-inset`（头像要落在 `--pane-px` 上）；信息面板的标签页比阶梯低一档（`--ctl-px-sm`，为了默认宽度放得下三个标签），顶栏左边相应让出 `--pane-px − 12`，第一个标签的字仍在 20 上。

**下拉菜单**：普通 `Menu`（`.menu-pop`）的项至少高 40，账户菜单使用 36（`--ctl-lg`）。项内缩进统一用 `--item-px`，长文字只在文字列换行。普通菜单的前导图标槽为 24；账户菜单直接使用 16 的线性图标，不加底色块，悬停和聚焦只高亮整行。同一菜单中有图标时，无图标的项也留出相同位置。账户菜单顶上是身份概览，上下内边距 8；余额在设置 › 模型中的 Modelflare 账户区 顶部常驻展示，通过留白区分账户余额和 Bot 额度；数字、图标和状态均使用语义色。

**规则与权限卡**：名称使用 `--fw-medium`，状态标题使用 `--fw-semibold`。权限卡的标题、说明、权限项和操作共用文字起始线；待授权和需要重新打开分别只突出一个主操作。撤销后的规则只弱化说明与划线标题，仍可用的恢复按钮保持正常对比度。模板名称用中等字重，添加按钮独占卡片底部操作区，避免长名称或译文与按钮重叠。

新规则、添加模板和返回模板使用现有的 `plus` / `arrowLeft` 线性图标，尺寸为 `sm`（14px），不在文案里拼接加号或箭头。正文中的连接入口保留行内排版，用下划线标明可点击部分。

**巡检**：改了 token 或组件后，用浏览器把各页面（对话、信息面板、发现、新建、设置各页、机器人设置、需要你、菜单、搜索、命令面板）在浅色 / 深色、四档字号、1440 / 1100 / 960 / 760 宽、Windows / macOS 标题栏、侧栏收起下各过一遍：没有横向溢出和裁切；胶囊的左右符合阶梯；每种容器的内容线符合上表；侧栏、顶栏、信息面板、弹出层的竖线在 20 / 20 / 20 / 16。

**写死的像素**只允许三种：`0`；≤1px 的细线（比如 `right: -1px` 压住描边）；同一行带 `/* 微调：理由 */` 注释的光学微调，守卫测试认这个注释。尺寸（宽、高、控件大小）不算间距，但 `calc()` 里加减的像素算（`calc(100% - 48px)` 其实是两侧的边距）。

## 品牌色

品牌色是 Modelflare 的**信号黄绿 `#d7ff00` + 墨色 `#161a00`**。界面骨架是纯灰阶（布局参考 Grok Bot / Codex），颜色留给机器人头像和状态。

用户头像使用 `UserAvatar`（`components/user-avatar.js`）：沿用 Modelflare 的 12 色色板、名称哈希和 135° 渐变，起止色不透明度为 62% / 46%，边缘是起始色的 34%。侧栏与头像菜单共用组件，同一名称固定配色；文字随深浅主题切换，悬停与展开时保持渐变。

**常规操作是中性的（浅色墨、深色近白），黄绿用于小信号和模型档位滑块。** 用户 2026-11-03 要求减少酸性色，尤其是作为背景色；2026-11-12 指定将模型选择器的性价比、模型智能滑块改为更纤细的品牌色微渐变。

| 角色 | token | 浅色 | 深色 |
|---|---|---|---|
| 主操作：主按钮、打开的开关 | `--primary` / `--on-primary` | 墨底白字 | 近白底墨字 |
| 模型档位滑块：性价比、模型智能 | `--brand` / `--on-brand` | 黄绿微渐变 + 墨色圆钮 | 同左 |
| 发送 / 停止 | `--send-bg` / `--send-fg` | 墨色圆钮 + 黄绿箭头 | 近白圆钮 + 墨色箭头 |
| 焦点、勾选、链接 | `--accent` | 墨色 | 近白 |
| 拖入文件、按钮的焦点光晕 | `--ring`（`--accent-soft`） | 中性 | 中性 |
| 选中文字、定位闪烁 | `--mark` / `--on-mark` | 一层灰 | 一层白 |
| 提示蓝点：侧栏里等你处理的机器人和「需要你」、上新、未读、回到底部、新版本 | `--signal` | 蓝 `--blue-500` | 蓝 `--blue-400` |
| 应用标志 | `--brand` / `--on-brand` / `--brand-line` | 黄绿底墨字 | 同左 |

黄绿用于浅色的发送箭头、应用标志和模型档位滑块。滑块轨道高 24px，圆钮 20px，内缩 2px；填充使用静态微渐变，两个滑块都拉满时保留流动渐变彩蛋。**其他区域不要用黄绿铺底**：按钮、提示胶囊、选中态、进度用中性色；状态（成功、工作中）用 `--green`，不要用黄绿冒充。

**数据图表**使用 `--chart-1 … --chart-4`（蓝、青、紫、琥珀），浅深主题分别定义。同一指标的数字卡、图例、柱线保持一致；同时提供名称、数值和箭头，不能只靠颜色区分。数据系列色不表示好坏，不能把成本增长等同于成功状态。金额与百分比分图，标明单位、期间与比较基期；柱图保留零线和负值，缺失观测处断开折线。

**余额**（设置 › 模型中的 Modelflare 账户区，`AccountBalance` 组件）：账户余额用较大数字，Bot 额度用次级金额、百分比与细进度条，刷新和充值直接可见。卡片使用同一层背景，以留白分组。低于提醒线时数字不变色，只增加一行带琥珀色小点的说明；加载中或读取失败不显示为零。侧栏只保留账户菜单，不再使用余额圆环和悬停提示。

## 材质

窗口只有几种面，越往上越亮。层次靠底色，不靠线、投影和透明（参考 Codex、Grok）。

| 层 | 是什么 | token |
|---|---|---|
| 窗口底色 | 窗口最底层，侧栏就是它：一层纯色的中性灰，不放光晕、不随机器人变色（用户 2026-11-03 要求）。`.app`、引导页、样例页的 `.window-bg` 共用 | `--bg`（`--glass-side` 是透明） |
| 主区、信息面板、引导页卡片 | 窗口底色上的圆角面板，四周留 `--pane-gap` | `--surface`、`--glass-panel`，`--shadow-pane` |
| 设置主面板 | 独立背景层的轻毛玻璃，24px 背景模糊、微弱高光与细边；窗口底色带轻微冷灰渐变 | `--settings-canvas`、`--glass-settings`、`--glass-settings-sheen`、`--glass-settings-edge` + `--glass-filter` |
| 顶栏、回到底部 | 盖在滚动内容上，几乎不透，内容从底下滚过只隐约看得到 | `--glass-chrome`、`--glass-float` + `--glass-filter` |
| 对话输入框 | 盖在滚动内容上的一块实色填充，比主区深一档 | `chat.css` 的 `--composer-bg` |
| 下拉菜单、头像菜单、模型选择器 | 半透明毛玻璃，轻微渐变高光、内沿细边与柔影；文字保持不透明 | `--glass-menu`、`--glass-menu-sheen`、`--glass-menu-edge` + `--glass-filter-lg`、`--shadow-menu` |
| 命令面板、提示、对话框 | 最上层，基本是实色 | `--glass-pop`、`--glass-sheet` + `--glass-filter-lg` |

写法：

```css
.pop { background: var(--glass-pop); backdrop-filter: var(--glass-filter-lg); box-shadow: var(--shadow-pop); }
<div class="glass" style="--glass-bg: var(--glass-chrome)">…</div>   /* 临时用：.glass + --glass-bg / --glass-blur / --glass-shadow */
```

不加磨砂颗粒。下拉浮层用轻微的渐变高光和内沿细边表现玻璃厚度，背景模糊沿用 40px；浅色底色不透明度为 76%，深色为 86%，避免深色菜单被背后的亮色内容冲淡。设置主面板使用更轻的 24px 模糊，透明底色只画在独立背景层，内容保持清晰；降低透明度时同时恢复实色面板和纯色窗口底色。

- **填充、悬停都是半透明的一层**（`--pill*`、`--side-*`、`--fill-field*`、`--sel*`），放在玻璃和实色上都对。不要在玻璃上用实色灰。
- **`backdrop-filter` 和 `transform` 会让元素变成 `position: fixed` 子元素的包含块**。对话框（`.scrim`）还是渲染在原地的，所以侧栏、主区、`.chat` 不要加；下拉不受影响，`Popover` 挂在 `<body>` 下。
- 系统开了"降低透明度"（`prefers-reduced-transparency`，解析成 `<html data-glass="off">`）时，盖在内容上的几样换成实色、`--glass-filter*` 变成 `none`，下拉浮层也去掉高光。不支持背景模糊时，菜单保留接近实色的底色；两种情况都保持文字可读。
- **模糊只给浮层及设置面板的独立背景层**：对话框、命令面板后面的遮罩只压暗、不模糊——对话框自己的玻璃已经模糊了一层，两层叠在一起既糊又费 GPU。

## 容器与层次

一句话：**成组靠底色和间距，不靠线；一组里面不再套一组；投影只给真正浮在内容上的东西。**（用户 2026-11-09 要求：整个客户端少用线段，输入框也不描边，干净整洁。）

| 层 | 是什么 | 底色 | 边 | 投影 |
|---|---|---|---|---|
| 0 窗口 | 窗口底色、侧栏 | `--bg` | 无 | 无 |
| 1 面板 | 主区、信息面板、引导页卡片 | `--surface` / `--glass-panel` | 无（靠底色和窗口分开） | 无 |
| 2 组（只有这一层） | 设置分组 `.list`、提问 / 审批卡 `.card`、代码块、文件、模板卡、行内提示、展开的编辑区 | `--well`，可点的组悬停 `--well-hover`、按下 `--well-press` | 无 | 无 |
| 组里的东西 | 行、命令、选项、按钮、输入框 | 直接排在组里，行与行之间靠行高分开；输入框是一块 `--fill-field` | 无 | 无 |
| 顶栏 | 盖在滚动内容上 | `--glass-chrome` | 无 | 无 |
| 3 常驻浮件 | 回到底部、提示胶囊；对话输入框是一块实色填充，不描边、不加投影 | `--glass-float` / `--glass-pop` | 一道细线 | `--shadow-float`，很淡 |
| 4 临时弹出 | 菜单、引导卡片、窄窗口的抽屉 | `--glass-pop` | 一道细线 | `--shadow-pop` |
| 5 模态 | 对话框、命令面板，后面有遮罩 | `--glass-sheet` / `--glass-pop` | 一道细线 | `--shadow-modal` |

- **选中、悬停都是平的**：侧栏行、设置导航是同一种灰深一级（`--side-hover` → `--side-active`），没有投影、不浮起。
- **一层只有一种写法**：要加新东西时先想它在第几层，照那一层写，不要自己调投影。
- **深色下越往上越亮**：`--bg` → `--surface` → `--glass-float` / `--glass-pop` → `--glass-sheet`，投影只是辅助。

- **不嵌套**：`--well` 里不再放 `--well`、卡片或描边框。审批卡里的 `write_file …` 就是一行等宽字；选项字母平时只是一列字，选中才填成一块（这是状态，不是容器）；图标不套底片（模板卡选中时图标换成主操作色的一片，也是状态）。对话框里不再套卡片："更换密钥"的表单直接排在对话框的内边距里。信息面板上的行直接排在面板上，只有展开的编辑区和待审批是一层 `--well`。
- **输入框是填充，不描边**：`.field` 是一块 `--fill-field`（半透明，放在主区、信息面板、对话框、`--well` 上都认得出），悬停、聚焦深一级，聚焦再加一圈和填充同色的淡光晕；对话输入框是一块比主区深一档的实色。系统高对比度模式（`forced-colors`）下没有填充，补回一道系统色的边。
- **常驻的边只剩**浮层玻璃的细边 `--glass-edge`，以及应用标志的墨色细边 `--brand-line`（黄绿在白底上只有 1.15:1）。
- **不画分隔线**：列表行、菜单分组、"用时"下面、设置里的块与块之间都靠间距；菜单的 `li.sep` / `hr` 只是一段空。剩下的线只有表格表头下沿（`--line-2`）、正文 `hr` 和引文的灰色竖线。表格不画格子：没有外框、竖线、行线和表头底色，第一列贴着正文左边。
- **不加侧边色条**：提示 `.notice` 是一行淡底（`--red-wash` / `--amber-wash` / `--well`）+ 左边一个图标 + `--fg` 的字（在淡底上 ≥ 14:1）；语气靠图标颜色，不要"淡红底 + 红边 + 左侧粗红条"，也不要淡红底上的红字（对比度不够）。引文 `blockquote` 的灰色竖线是排版记号，可以留。
- **描边和投影不另外叠加**：内容里的组两样都不要；浮层只用 `--shadow-float / -pop / -modal`（细线已经在里面）；分段 thumb、开关圆钮只有 `--seg-edge`。
- **状态用点，不用彩色胶囊**：`.badge` 是"状态点 + 文字"（和设置页的「● 已连接」同一种写法）；计数 `.badge.count` 只留在信息面板、连接页的分组标题里。**侧栏不用数字标签**（用户 2026-11-09 要求）：等你处理的机器人行和「需要你」右边只有一个蓝点 `.needs-dot`（`--signal`），件数写在 title 和读屏文字里；头像等你时照样跳，但不冒感叹号。
- **小标签**：分组名、菜单分组一律 `.t-label`（12px semibold、`--muted`），不全大写、不加字距、不用 `--faint`（读不清）。
- **同一种面同一个圆角**：面板 `--r-pane`（24）、大卡片 `--r-card-lg`（20）、小卡片 `--r-card`（16），气泡 `--r-bubble`（24）、对话输入框 `--r-composer`（28）；能点的控件是胶囊（`--r-ctl`）。见「形状」。
- **不用装饰性 emoji**：服务端用 `⚠️` 标记出错的消息（微信、飞书里只能这样），界面里显示前去掉，语气交给 `Notice` 的图标。

**可交互的东西要认得出来**（非文字对比度 ≥ 3:1，或者有等效的提示）：

- 输入框：靠填充、上方的标签和常显的占位文字（`--placeholder`，3:1）认出来；聚焦时填充深一级 + 淡光晕。高对比度模式下有系统色的边。
- 对话输入框认得出它靠比主区深一档的实色、常显的占位文字、工具栏和发送钮、固定在底部的位置；侧栏搜索框靠放大镜图标 + 占位文字 + 底色，聚焦时换成实色面。
- 按钮、分段、开关、下拉靠文字和填充；键盘焦点一律 2px accent 描边（`:focus-visible`），输入框是填充深一级 + 淡光晕。

真的需要一道边时，在**同一行**写 `/* 描边：理由 */`，守卫测试认这个注释（`ui/` 下除 token 文件外的所有 CSS）。

## 状态

每个可交互组件都要把下面这些状态想到；样例页的「状态矩阵」把它们按浅色 / 深色并排画出来（伪类规则被复制成 `.is-hover / .is-active / .is-focus`，和真实交互是同一份样式）。

| 状态 | 怎么表现 | 用什么 |
|---|---|---|
| 悬停 | 叠一层半透明，静默控件的字从 `--ctl-fg` 变 `--fg`；可点的组（模板卡）底色深一级，不浮起、不加描边 | `--pill` → `--pill-hover`，`--well` → `--well-hover`；侧栏里是一层淡灰 `--side-hover` |
| 按下 | 再深一级，不缩小、不回弹 | `--pill-press`、`--sel-press`、`--side-press` |
| 键盘焦点 | `:focus-visible` 2px `--accent` 描边；输入框是填充深一级 + 淡光晕 | `--focus-offset`、`--field-ring` |
| 打开 | 菜单展开时触发它的按钮保持"按住"的样子，箭头翻转，加号转成叉 | `[aria-expanded="true"]`，`.icon-btn.on` |
| 选中 / 当前 | 侧栏行和设置导航是同一种灰深一级，没有投影；菜单当前项打勾；模板卡底色深一级、图标换成主操作色的一片；头像选择是底色深一级 + 名字变实（头像在"听"）。都不描边 | `--side-active`，`--well-press`，`--pill-press` |
| 禁用 | `--o-disabled`，不响应悬停和按下；主按钮和发送钮退成中性灰（半透明的主操作色会发浑） | `:disabled` |
| 加载 | 转圈，颜色不变，只是不可点（`aria-busy`） | `Button loading` |
| 错误 | 铺一层淡红，聚焦时红光晕 | `.err` / `aria-invalid`，`--red-wash`、`--ring-danger` |
| 只读 | 次级底，聚焦不发光 | `[readonly]` |
| 滚动边缘 | 顶栏不画线，内容滚到底下时只靠毛玻璃 | `--glass-chrome` |

## 分隔条

两块面板之间的空隙可以拖：侧栏 | 主区、主区 | 信息面板。组件是 `Splitter`（`ui/components/ui.js`），样式在 `components/splitter.css`。

| 方面 | 规范 |
|---|---|
| 位置 | 就是面板之间那道 `--pane-gap` 空隙，分隔条的中线落在空隙正中；能抓住的宽度 `--split-hit`（12）比空隙宽一点，两边各探进面板 2px。Electron 里是 `no-drag`，盖在顶栏的拖动区上也抓得住 |
| 平时 | 看不见，指针移上去只变成 ↔（`col-resize`） |
| 悬停 | 停住 `--dur-intent` 后空隙中间从中点长出一道 2px 的细线 `--split-line`；只是划过去不闪，移开立刻消失。细线只画在面板直边那一段（上下让出 `--pane-gap + --r-pane`） |
| 拖动 | 细线换成 `--split-line-on`（`--accent`：浅色墨、深色近白）；整个窗口都是 ↔、不会选中文字（`<html data-resizing>`）；宽度跟手（直接写 CSS 变量，不经过渲染，列宽不过渡）；离默认宽度 6px 以内吸附回默认；到了最窄 / 最宽，指针换成单向箭头 |
| 范围 | `--side-w-min … min(--side-w-max, --side-w-cap)`（220 … 400，且不超过窗口的 36%），右侧面板 `--panel-w-min … min(--panel-w-max, --panel-w-cap)`（280 … 440，34%）；放着工作台（专业 Bot 的专属界面）时是 `--work-w-min … min(--work-w-max, --work-w-cap, 窗口 − 侧栏 − --main-w-min)`（400 … 1200，64%，默认 `--work-w` 46%，和对话大约对半）；拖动时还要给主区留至少 `--main-w-min` |
| 恢复 | 双击分隔条恢复默认宽度，列宽用 `--dur-slow` + `--ease-spring` 滑回去 |
| 键盘 | `role="separator"`，可以 Tab 到；焦点就是那道 accent 细线（不画外描边）。← → 一次 8px、Shift 一次 32px，Home / End 最窄 / 最宽，Enter 恢复默认 |
| 保存 | 松手、键盘、双击时提交一次：`lib/prefs.js` 的 `sideW` / `panelW` / `workW`（px，0 = 默认；带工作台的面板单独记），每个窗口各一份；首帧前 `index.html` 先写到 `<html>` 上的 `--side-w-user` / `--panel-w-user` / `--work-w-user`，不闪 |
| 不出现 | 窗口窄于 1180px 时右侧面板是浮在对话上的抽屉，它的分隔条隐藏；带工作台的抽屉按 `--work-w-cap` 给宽，最多铺满窗口 |

页面怎么接：列宽在 `.app` 上用 `clamp(-min, var(-user, 默认), min(-max, -cap))` 算出来（`--side-col`、`--panel-col`），分隔条用 `--split-x` 定位到空隙中线：

```css
.app > .split-side { --split-x: calc(var(--side-col) - var(--pane-gap) / 2); }
<${Splitter} class="split-side" size="--side-w" label="调整侧栏宽度" value=${sideW} room=${…} onCommit=${(px) => setPrefs({ sideW: px })} />
```

`--side-col`、`--panel-track`（信息面板那一列此刻的宽度：关着是 0）注册成 `<length>`（`@property`，不继承），所以信息面板开合、恢复默认时列宽能平滑过渡：面板本身定宽，列变窄时它往右滑出窗口，里面的内容不会被挤扁重排。

## 主题

- `<html data-theme>` 总是解析后的 `light` / `dark`（`index.html` 首帧前设置，`lib/theme.js` 同步）。
- **主题可以局部生效**：任何元素加 `data-theme="dark"`，它的子树就换一套语义 token（样例页的双主题对照就是这样做的）。
- 因此**不要写** `:root[data-theme="dark"] .xxx { … }` 这类按主题的覆盖。需要两个主题不同的值，就加一个语义 token。
- 由其他语义 token 推导的值（`--ring`、`--code-bg`）写在 `:root, [data-theme] { … }` 里，每个作用域都会重新计算。

## 用户偏好

设置 › 外观（和常规里的发送键、通知）是**本机界面偏好**，和主题一样存在 localStorage（`amb-prefs`，`lib/prefs.js`），每个浏览器 / 桌面窗口各一份。外观类的偏好解析成 `<html>` 上的属性，`semantic.css` 的「用户偏好」块和 `motion.css` 把属性翻译成 token——**页面和组件只用 token，不认这些属性**：

| 属性 | 取值 | 翻译成 |
|---|---|---|
| `data-text` | `sm / md / lg / xl` | `--fs-scale`（.92 / 1 / 1.1 / 1.2）：只放大文字，控件高度、图标、间距不变；整体放大是桌面版的「界面缩放」（Electron zoom） |
| `data-font` | `system / serif / custom` | `--font`；`custom` 时 `prefs.js` 在 `<html>` 上内联 `--font: "自定义", var(--font-system)`。自定义代码字体同样内联 `--code` |
| `data-width` | `normal / wide / full` | `--col-w`、`--bubble-w`（对话列和输入框） |
| `data-code-wrap` | `on / off` | `--code-wrap`（代码块的 `white-space`） |
| `data-glass` | `on / off` | 不是用户设置，只跟随系统的"降低透明度"；翻译成材质（见「材质」） |
| `data-motion` | `full / reduce / off` | `--motion`、`--dur-*`（见「动效」） |

- 首帧前 `index.html` 的内联脚本按同样的规则先套一遍，避免闪；改解析规则时它和 `prefs.js` 的 `apply()` 一起改。
- "跟随系统"在 JS 里解析：属性永远是解析后的值，CSS 里不写 `@media (prefers-reduced-*)`。

## 图标

通用操作图标统一使用 [Heroicons 2.2.0 Outline](https://github.com/tailwindlabs/heroicons/releases/tag/v2.2.0)，保留官方 24 格画布、`currentColor` 和圆头圆角。`ui/icons/heroicons.js` 只包含应用用到的图形，内部名称保持兼容；上游文件名、固定提交和校验值记录在 `ui/icons/heroicons-source.json`，许可证随资源放在 `ui/icons/LICENSE`。品牌 Logo、机器人头像和数据图形独立维护。

| 档 | `size` | 像素 | 用在 |
|---|---|---|---|
| xs | `"xs"` | 12 | 下拉箭头（`.pick`、模型胶囊，上下文自动给）、`.icon-btn.xs` 里的关闭、实心圆点里的勾、列表行尾的 › |
| sm | `"sm"` | 14 | **默认**：`Button` / `IconButton` / `Notice` / 菜单的图标和勾、输入框尾部、行内操作（刷新、删除、复制）、侧栏和弹出层的搜索 |
| md | `"md"` | 16 | 顶栏与工具栏按钮（新对话、信息面板、关闭）、侧栏的新建 / 导航 / 账户 / 返回、对话输入框（加号、发送、停止、回到底部）、命令面板搜索 |
| lg | `"lg"` | 20 | 模板卡 |
| xl | `"xl"` | 24 | 文件卡片 |

- **线宽按显示像素算**：`--ic-stroke`（1.5px）对所有尺寸都一样，12px 的箭头和 24px 的文件图标一样细；`icon.css` 把它换算回画布单位（× 24 / 尺寸）。只有实心面上的图标加 `strong`（`--ic-stroke-strong` 1.75px）：发送钮的箭头、完成圆点里的勾——细线压在实心面上会发虚。不要再传任意的 `stroke`。
- **只用这五档**，不写 13、15、17 这类中间值。`Icon` 默认 `md`，`Button` / `IconButton` 默认 `sm`；兼容 12 / 14 / 16 / 20 / 24 的数字调用，并归一到相同的 CSS 档位。图标和旁边的文字差不多高或略高一点：14px 的控件文字配 14，侧栏和顶栏配 16。
- **上下文改尺寸只改 `--ic-size`**（`.pick .ic { --ic-size: var(--ic-xs) }`），不要直接写 `width / height`——那样线宽会跟着缩放。`icon.css` 全部包在 `:where()` 里，任何上下文选择器都能盖过 `size` 属性。
- **保持原图形**：使用 Heroicons Outline 的 SVG 节点，不改路径、不单独拉伸，不把图标压成一条自绘路径。尺寸与描边由共享组件和 token 控制，按钮的点击范围由控件尺寸控制。
- 新图标：从同一固定版本的 Heroicons Outline 选取语义对应的图形，补齐来源记录；在样例页「图标」中检查五档尺寸、两种主题，以及菜单和工具栏中的对齐。

## 动效

| 用途 | 时长 | 缓动 |
|---|---|---|
| 悬停、按下、颜色变化，下拉菜单出现 | `--dur-fast` 100ms（`--t-fast`） | `--ease-out` |
| 出现 / 消失、提示胶囊、对话框、视图切换 | `--dur-base` 140ms | 入场 `--ease-out`，退场 `--ease-in` |
| 分段 thumb | `--dur-moderate` 180ms | `--ease-out` |
| 布局滑动：信息面板开合、分隔条恢复默认 / 键盘调宽 | `--dur-slow` 240ms | `--ease-spring` |
| 悬停意图：停住多久才亮起提示（分隔条的细线） | `--dur-intent` 240ms | 只延迟出现，移开立刻消失 |
| 循环（转圈、骨架、文字微光、呼吸、光标） | `--dur-spin --dur-shimmer --dur-sheen --dur-pulse --dur-blink` | `linear` / `--ease-in-out` |

- **简约**（用户 2026-11-03 要求）：出现 / 消失只淡入淡出，不位移、不缩放、不回弹；按下只深一级底色。唯一的位移是窄窗口的信息面板抽屉；机器人头像的动作不算在内。
- **关键帧库**（`base/motion.css`）：`fade-in/out`、`slide-in/out`（只给抽屉）、`flash`、`spin`、`shimmer`、`sheen`（文字微光，配 `background-clip: text`）、`breathe`、`blink`。关键帧只描述起止，时长缓动由使用处给 token。
- **减少 / 关闭动画**：看 `<html data-motion>`（`full | reduce | off`，设置 › 外观 › 动画；跟随系统时看 `prefers-reduced-motion`）。抽屉的位移乘以 `--motion`；`reduce` 时 `--motion: 0`，抽屉退化成纯淡入，过渡几乎瞬时；`off` 时 `--dur-fast … --dur-slow` 也变成 `--dur-off`，出现 / 消失 / 视图切换瞬时完成，只留转圈、骨架、光标这类"正在进行"的循环和定位闪烁。新写的关键帧也要乘 `--motion`；CSS 里不要再写 `@media (prefers-reduced-motion)`，JS 用 `reducedMotion()`（`design/motion.js`）。
- **退场动画**：用 `usePresence(open)`（`design/motion.js`）让组件在退场时长内保持挂载，并给元素加 `.leaving` / `.anim-*-out`。`DialogHost` 是参考实现。列表里的行增删用 `useListPresence(items)`：新行淡入，删掉的行留在原位淡出，见侧栏的机器人列表。
- **JS 里不写死毫秒数**：`ms("--dur-base")` 读 token（toast 的移除时机就是这样同步的）。
- **每个动画都要有明确的表意**：只用来表达状态变化（出现 / 消失、选中、成功 / 失败）、对操作的反馈、真实在进行的过程（加载、生成、传输）、机器人的状态。**严禁背景 / 装饰层的动画**——背景、光晕、边框、纹理一律静止：不做自己循环的光圈 / 光框扩散（"隧道"、涟漪、雷达波）、呼吸的光晕、沿边框巡游的扫光、漂浮的光斑 / 粒子、跟随指针的点阵 / 聚光灯。说不出"它在告诉用户什么"的动画一律不加（官网同一条，见 `site/README.md`）。
- 只给 `transform` 和 `opacity` 做动画；空闲列表保持安静（头像空闲时只在指针靠近时看过去、悬停时抖一下天线，不自己动）。唯一的例外是对话里很快答完时工作状态行的收起（`.work.gone`，grid `1fr → 0fr`，只播一次），为的是正文不跳。

**对话流的编排**（`ui/css/chat.css`）：发出 → 思考 → 输出 → 收尾，每一步只动一样东西，只淡入淡出，循环都放慢、对比只差一档，余光里知道"在动"就够了。

| 环节 | 动什么 | 怎么动 |
|---|---|---|
| 发出 | 你的气泡 | `fade-in`（base） |
| 思考 | 工作状态行 | 比气泡晚 `--stagger` 淡入；"思考中"是 `sheen` 微光 |
| 输出 | 新段落 / 列表项 | 新挂载的块淡入（moderate），已在的不重播；最后一段末尾一个 `breathe` 小点（代码块、表格结尾不画） |
| 收尾 | 状态行、操作 | "用时"换字淡入；短于 3 秒的整行平滑收起；最后一条回复的复制 / 时刻晚一拍淡入 |
| 插入 | 提问 / 审批卡、出错提示、交付的文件 | `fade-in` |
| 输入框 | 发送钮 | 发送、停止互换时图标淡入；点发送 / 停止不抢输入框焦点 |
| 其他 | 首次加载、回到底部 | 历史读到后整列淡入一次；回到底部淡入淡出 |

## 文案

- 最短、能说清就行：不加解释性的括号，不写说明段落。健康、空闲时什么都不显示。
- 一行里有状态，又跟着别的状态或事实（时间、花费、次数）时，写成一句自然的短句，不用「·」把碎片串起来：

  | 写成 | 不写成 |
  |---|---|
  | 进行中，有个问题等你回答 | 进行中 · 有个问题 |
  | 已进行 12 分钟，花了约 $0.08 | 进行中 · 12 分钟 · 约 $0.08 |
  | 观察中，明天 08:00 再运行 | 观察中 · 下次 明天 08:00 |
  | 第 1 次运行，用了 12 分钟 | 第 1 次 · 开始 · 34 步 · 12 分钟 |
  | 天天的「GPU 价格调研」在等你回答 | 天天 · GPU 价格调研 · 等你回答 |
  | 后台任务「GPU 价格调研」进行中 | 后台任务 · GPU 价格调研 · 进行中 |
  | 规则「看 X 价格」已观察 3 次，需要你来决定是否执行 | 已观察 3 次 · 改为执行？ |

- 句子里不帮人做决定的细节直接去掉，不往句子里塞（上面的「开始」「34 步」就是这样去掉的）。
- 不把「·」换成逗号了事：「Marla，由企业钱包付费」「需要你的批准，编号 A7K2」这样只是标签加碎片的，要么写成一句不带逗号的完整的话（「Marla 的费用由企业钱包支付」），要么留着「·」（「需要你的批准 · A7K2」）。
- 「·」只留给没有状态词、让人扫一眼的紧凑元信息：模型的上下文 · 能力 · 价格，「微信 · 3 天前」这样的来源和时间，运行记录展开后的「第 1 版 · 只读 · 手动运行」，诊断信息。
- 英文同样写成自然的句子，不照搬中文的断句：「Observing, next run tomorrow 08:00」「Run 1 took 12m 0s」「Ping: “GPU price research” is waiting for your answer」。句中的 today、tomorrow 小写。
- 中文、英文都要有（`ui/locales/`，服务端的在 `src/i18n/messages/`）。

## 新增或修改

1. 先在样例页里找现成的 token、组件、文字角色。
2. 缺颜色 → `semantic.css` 加语义 token（浅色、深色各一个值）；缺间距 → 先找同一用途的间距角色，没有再在 `semantic.css` 的间距块里加一个（取值来自 `--space-*`）；缺尺度 → `primitives.css`。
3. 新组件 → `components/<name>.css`，开放 `--<name>-*` 变量，在 `index.css` 按层引入；需要逻辑时在 `ui/components/ui.js` 加 JS 写法；在 `gallery.js` 加样例。
4. 页面专属样式写在 `ui/css/*.css` 的 `@layer app` 里，只引用 token。
5. 跑 `npm test`。

## 守卫测试会拦下

- `ui/design/tokens/` 之外出现原始颜色（`#hex`、不含 `var()` 的 `rgb()/hsl()`）
- 圆角用了 primitives（`--r-xs … --r-full`）或兼容名 `--r-well`，或用了 50% 以外的百分比（同一行写 `/* 形状：… */` 的除外；样例页除外）
- `font-size` / `font` 里写死 px
- `border-radius` 写死 ≥ 3px（1–2px 的细节、`50%` 不算）
- `transition` / `animation` 里写死时长或缓动（`linear`、`steps()` 可以）
- `z-index` 写死数字
- 间距写死 px：`margin` / `padding` / `gap` / `inset` / `top|right|bottom|left` / `scroll-margin|padding`，以及 `--*-gap|pad|px|py|pl|pr|pt|pb|inset|gutter` 这类间距变量；`calc()` 里加减写死的 px。0、≤1px 细线、同一行带 `/* 微调：… */` 注释的除外
- JS 内联样式里写死颜色、字号或间距
- 描边容器：`border` / `outline` 带宽度，或 `box-shadow`（包括自定义属性的值）里画一圈 `0 0 0 <宽>` 的边，而同一行没有 `/* 描边：… */`；`:focus*` 选择器里的焦点描边除外
- 侧边色条：左右两侧 ≥ 2px 的 `border`，或 `box-shadow: inset Npx 0 0`；以及上下 > 1px 的分隔线（`var(--hairline)` 算 1px）
- JS 内联样式里画边框
- `text-transform: uppercase` 和正的 `letter-spacing`（小标签不全大写、不加字距）
- 引用了没定义的 `var(--x)`（带回退值的除外）
- 有组件或基础样式文件没在 `index.css` 里引入

组件文件里确实需要的"魔法数"（比如头像的眨眼周期），先起名再用：`--bf-blink: 4.2s`。自定义属性的定义不受时长规则限制，但要写清楚用途。
