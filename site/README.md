# AnyModelBot 官网（site/）

Astro 5 静态站，Preact 只用在价格表、计算器（含可搜索的模型选择框）这几个岛上；样式是原生 CSS + token（`@layer tokens, base, components, app, utilities`），品牌色与 App 的 `ui/design` 相同。规格见《AnyModelBot Landing Page · 需求与样式设计稿 v3》。

## 页面结构

- **首页**（`src/views/Home.astro`）八块，每块讲清一件事，细节交给附属页：
  1. Hero：圆角大卡片里放标题、一句说明、下载 / 演示、一行小字要点，底下一台桌面窗口 + 一部手机循环演示（宽屏两侧有流动卡片）
  2. 认识你的机器人（一排角色 + 挂在挂绳上的工牌 + 手机 mock；工牌上的"月薪"是月估算，链到 /pricing 的计算器）
     - **角色的名字**：中文叠字、英文一个词，都取自它最显眼的那件配饰——天天 Ping（天线）、闪闪 Twinkle（星星）、芽芽 Sprout（嫩芽）、哒哒 Beat（耳机）、晶晶 Crystal（水晶）、飞飞 Pilot（飞行护目镜）。文案在 i18n 的 `bots.chars`：`name` 本语言名、`alias` 另一种语言的名字（只有中文页写英文名；英文页留空，不出现中文名）、`lead` 讲名字的由来。工牌上名字旁边写 alias；证件照上不加标注（指向配饰的小标签已去掉，没有意义）。代码里的键仍是颜色（blue / yellow / green / red / purple / orange）。
  3. 能动手、会记住：两章边滚边讲（左边文字依次滚过，右边吸顶的舞台卡跟着换场）
  4. 任意模型：居中章节头两侧散落一片毛玻璃厂商图标砖（有标志的厂商、不放快手；标志用官方彩色版；砖越大、越靠近标题，这家的模型越多；每块很轻地上下浮动，悬停显示厂商名，窄屏少放、手机不放），标题下一颗公式胶囊「1 个 Key → N 个模型 · M 家厂商」（`components/ModelsHeadArt.astro`，数字取自价格快照）→ "换脑"舞台（模型环绕晶晶转 + 对话演示）→ 一行模型名跑马灯 → 三栏价格面板（完整价格表、计算器在 /pricing）
  5. 数据去向图（长版在 /security）
  6. 在哪都找得到它（安装包与校验在 /download）：一张切换台——左边入口清单，右边示意小图 + 具体做法（直链、命令、接入步骤）。入口是桌面、Docker、浏览器 + 聊天渠道。渠道按语言不同——中文页微信、飞书，英文页 Slack、Telegram、Discord（参考 [OpenClaw 支持的 IM](https://docs.openclaw.ai/channels)；英文页不出现微信 / 飞书），在 `src/data/channels.ts`
  7. 常见问题
  8. 收尾横幅（和首屏呼应：静止的大卡，跟着页面主题走——顶光 + 一层星空（深色小星点 / 浅色细小闪光）+ 底边一道扁扁的地平线，六个机器人站在地平线后面探出半个头；高度收紧，不设最小高度）
- **章节头**：`components/SectionHead.astro`——一列左对齐：细线 → 编号 / 名称 → 两段式标题（后半句次要色）→ 说明，主持机器人蹲在细线右端（规范见下文"排版规范"）。
- **机器人互动**（`lib/eyes.ts`，台词在 i18n 的 `quips`）：戳一下回一句、连戳冒爱心 / 晕，鼠标在大头像上来回蹭会撒娇；`[data-doze]` 里的机器人 20 秒没动静会挨个打瞌睡，一动就惊醒并嘴硬；循环示意用 `data-states` / `data-shots` / `data-say-at` 驱动机器人（`scripts/tour.ts`）。
- **页脚**（`components/Footer.astro`，每页都有）：品牌（标记 + 一句话）｜ 产品 / 资源 / 法务三栏 → **收录徽章**（“被收录于 / Featured on”，目录站要求的徽章和反链，原码在 `data/badges.ts`，写进静态 HTML，图片外链到站方并懒加载，手机上是一行横滑；删徽章可能导致下架）→ 版权行 → **眼睛田**：最下面的 AnyModelBot 大字标由几百枚迷你 Eyes 标记拼成（一格一张小机器人脸，比例和 `EyesMark.astro` 一致），画在 canvas 上（`scripts/eyefield.ts`，纯逻辑在 `lib/eyefield.ts`）。宽屏一行、手机三行（按画布比例判断，比例由 `footer.css` 定）。每个动作都对应产品本身：
  - **醒过来**：第一次滚到时从左到右一张张弹出来、睁眼（内容出现）。
  - **看着你**：所有眼睛跟着指针看，鼠标附近的脸探出头、眼睛睁大，按住时一起眯眼（机器人的反应）；指针离开就自己东张西望、偶尔眨眼。
  - **发消息**：点一下（手机上点一下），从那里按远近一张张眯眼笑——"挨个收到了"（对点击的反馈；不画扩散的圈）。
  - **换脑**：每 7 秒一道斜波扫过，扫到的脸眨一下眼、睁开就换成另一个机器人的眼睛色；右上角同时换成下一个真实模型 ID（价格快照里每家厂商取一个）。讲的是"任意模型，还是这群机器人"（内容切换）。
  - **打瞌睡**：9 秒没人动，慢慢闭眼、目光耷拉；指针一动，从指针那里一圈圈醒过来（机器人的状态，同 `[data-doze]`）。睡着时不换脑。
  - 只在页脚进视口、标签页可见时跑；"减少动态效果"时画一张静止的字标；无 JS 时整块不显示。配色：深色是灰面罩 + 发光的眼睛；浅色是淡彩面罩 + 墨色眼睛——每张脸的面罩用它那个角色的辉光色调进底色、从字标顶到底由浅变深，一圈极细的边，整块像一片粉彩马赛克，"换脑"时整片换色调（不用整块墨色，也不出现白底上的荧光色）。字标盒子贴着字形（宽屏 7.4:1、手机 1.3:1），画布上下各出血 16px 给探头的脸，不额外留白。
- **附属页**：`/pricing`（价格卡、订阅制对照、价格表、计算器）、`/download`（四个平台、校验、Docker、CLI）、`/security`、`/changelog`、`/privacy`、`/licenses`。
- **导航**（`components/Nav.astro`）：通栏，和正文同一个容器——logo、下载按钮分别对齐内容的左右边线，链接居中：机器人 · 功能 · 模型 · 数据（首页锚点）· 价格（独立页）· 文档。停在顶上时透明，滚动后铺半透明底色和一根底线。一套尺寸到底：所有控件（含下载按钮）都是 32 高的胶囊，文字 14、图标 16，控件之间 2px、工具组和下载之间 12px。
- **顶部公告条**（`components/SiteBanner.astro`，内容在 `src/data/announcements.ts`）：发版条（版本取自 `releases.json`，按访客系统直接下载对应安装包，发布后显示 30 天）+ 宣传 / 公告，多条时轮播、可翻页；支持时间窗、截止倒计时、按 id 记住关闭；浏览器语言和页面不一致时附带语言切换。地址加 `?banner=preview` 可预览全部条目。埋点 `banner_view` / `banner_click` / `banner_dismiss`。

### 配色

深色是默认主题，浅色是 `html[data-theme="light"]`。品牌色是黄绿 `#d7ff00` + 墨色 `#161a00`，和 App 一样：**深色下黄绿负责操作；浅色下墨色负责操作，黄绿只做"墨色上的光"或一层很淡的底。** 黄绿在白底上只有 1.15:1、彩度又极高，大面积铺在浅底上会发荧光，所以浅色里不出现成块的纯黄绿。

组件只用语义 token，不直接写 `var(--accent)` / `var(--lime)` 当填充：

| 用途 | token | 深色 | 浅色 |
|---|---|---|---|
| 主按钮、分裂按钮右段、跳转链接 | `--primary*` / `--on-primary` | 黄绿底墨字 | 墨底白字 |
| 主操作色面上的 Eyes 标记（`data-on="accent"`） | `--primary-mark-*` | 墨色标记 | 黄绿标记 |
| 小块实心记号：公告条标签、手机 mock 的发送键 | `--signal-bg` / `--signal-fg` | 黄绿底墨色 | 墨底黄绿 |
| 成排出现的品牌标签（`.badge--accent`："默认""本地"） | `--tag-*` | 实心黄绿 | 淡底 + 深橄榄字 + 细边 |
| 荧光笔 `mark.hl`、文字选区、"我"的气泡、Hero 的记忆卡 | `--hl-bg`、`--bubble-me` | 黄绿 | 柔黄绿 `--lime-soft` |
| 文字、链接、图标、细线、小光点 | `--accent-fg` | 黄绿 | 橄榄 `#5f711c` |
| 图标底片、选中的 chip、焦点外圈 | `--accent-wash`、`--chip-on-bg` | 14% 黄绿 | `#eff7d7` |
| 菜单、下拉、Toast、对话框的投影与遮罩 | `--shadow-c`、`--shadow-c-strong`、`--scrim` | 黑色 | 中性冷灰 `rgba(17, 24, 39, …)`，轻而散 |

**浅色的层级**只用中性的白和灰（冷一点点，不偏黄、不偏绿；细线、投影也是中性冷灰，不带墨绿），从下往上：

1. 页面浅灰 `--bg` `#f4f5f7`，底下一层静止的环境光（`base.css` 的 `body::before`：几团很大的白光和一点冷灰，固定在视口上）；
2. 舞台卡（`.stage`、`.crew`、`.story__scene`、价格面板、收尾大卡）：半透明的白 + 颗粒 + 顶边高光，透出底下的环境光；底光的位置换成一团更亮的白，**不铺角色色**；
3. 舞台上的卡片、浮层：白玻璃（`--glass` / `--glass-strong`）；
4. 凹槽回到浅灰 `--bg-sunken` `#f1f2f5`（输入框、对话气泡、数据去向的节点）。

角色色和黄绿在浅色下只留在小记号上：选中态、图标、圆点、挂绳和头顶的光束、流动的光点。

**机器人色的浓度**统一乘 `--glow-k`（深色 1、浅色 .55）：舞台底光、选中态的底和描边、示意图里的色块都写成 `calc(N% * var(--glow-k))`，浅色不用再逐条覆盖（浅色下舞台、场景卡、示意图的底另有规则换成白光，见上面"浅色的层级"）。浅色下带模糊的发光小点（`0 0 12px var(--tint)` 这类）换成一圈淡色描边。

**通透感**：两个主题的 `body::before` 都有一层静止的环境光（浅色几团白光 + 一点冷灰；深色白光只有 2.5–4.5%），没有颜色、不动。舞台卡、卡片、价格面板、表格、计算器在深色下是 80% 的半透明底 + 颗粒 + 顶边高光，透出底下的明暗；浅色下是半透明的白（见上文）。

**毛玻璃**（`tokens.css`，和 App 的材质同一套）：`--glass`（胶囊、标签、舞台上的卡片）/ `--glass-strong`（菜单、下拉、对话框、抽屉、吸底条）+ `--grain` 磨砂颗粒 + `--glass-ring`（顶边一线高光 + 细边）+ `--glass-blur` / `--glass-blur-lg`。只给浮在内容上、或叠在舞台上的东西用；铺满整节的大面不用。浅色下价格卡、计算器、表格、FAQ 的条也用玻璃的颜色（半透明白 + 细边 + 顶边高光）。
`backdrop-filter` 只加在背后真有东西可模糊的地方（导航、菜单、对话框、次按钮、舞台上的小窗口）。**里面有弹出层的卡片不加**（价格卡、计算器表单、数据去向的几栏）：它会让卡片自成层叠上下文，把下拉菜单、说明卡关在里面，被旁边的卡盖住。大面积的舞台卡也不加——背后只有很柔的环境光，模糊不出东西。导航的毛玻璃画在 `.nav::before` 上，导航本身不带 `backdrop-filter`，里面的菜单才模糊得到页面。

**纵向节奏**（`tokens.css`）：一节上下各留 `--section-y`（72–112，两节之间最宽 224）→ 章节头到内容 `--stack-head` → 同一节里两大块之间 `--stack-block` → 舞台卡到它下面的说明 / 按钮 `--space-8`。卡片里：标题行和内容之间用一根细线分开（数据流的栏、下载卡的"校验"、多端的做法列表），内边距和间距都取 4 的倍数。

**圆角**：按钮 / 胶囊 `--r-btn`，弹出层 `--r-pop`（14）→ 里面的行 `--r-item`（10），输入框 / 代码块 / 提示条 `--r-field`（12），小卡 `--r-shot`（16）、卡片 `--r-card`（20）、大卡和对话框 `--r-feature`（24）、舞台 `--r-banner`（32）。

背景里的光浅色下不带颜色：公告条的 `--glow-brand` 是白光，Hero 的环境色、地平线只剩一丝机器人色；角色色（尤其芽芽、闪闪）在浅底上也收一档（`.crew` 的 `--beam-mix` / `--photo-mix` / `--dot-glow`）。

### 排版规范

字号都在 `tokens.css`，写样式时用 token，不要另写一次性的字号。

**字体只有两种。**
- Geist（中文回退到苹方 / 微软雅黑）：所有标题、正文和标签。
- Geist Mono：只用在机器读得懂的内容上——模型 ID、命令、路径、文件名、价格数字、编号。
- 英文页面整页不出现中文：角色不写中文名，语言切换写 ZH / Simplified Chinese，提示条写 "This page is also available in Chinese"，第三方声明用 `THIRD_PARTY_NOTICES_en.md`，读屏文字用英文标点。
- 中文页面里写着中文句子的标签一律用无衬线，包括 `.eyebrow`、`.badge`、步骤、连线说明。Hero 要点两种语言都用无衬线。
- 等宽字体栈末尾带了中文黑体，混进等宽元素的中文不会落到 Windows 的新宋体。

**标题四级。** 相邻两级约差 1.5–1.6 倍，字重一律 600：

| 级别 | 类 | 英文 | 中文（`-zh`） | 行高 英 / 中 | 字距 英 / 中 | 用在 |
|---|---|---|---|---|---|---|
| display | `.hero__h1` | 42–76 | 38–72 | 1.02 / 1.16 | -.045em / -.02em | 只给 Hero；行尾的天天 1.12em（手机 .86em） |
| h2 | `.h2` | 32–56 | 26–48 | 1.06 / 1.25 | -.035em / 0 | 章节标题、收尾横幅、附属页 H1 |
| title | `.subhead` | 26–36 | 24–32 | 1.12 / 1.3 | -.025em / 0 | 章节里的块标题：功能卡、价格概览、工牌上的名字 |
| h3 | `.h3` | 22（手机 20） | 同英文 | 1.3 | — | 卡片、弹窗标题 |

中文字面比拉丁字母满，所以中文标题小一档：字距不收，行高放开 .15–.2。

**正文。**
- `--fs-lead`（17–19）：Hero 说明、章节说明、FAQ 问题
- `--fs-body-lg`（17）：功能卡说明、要点标题
- `--fs-body`（16）
- `--fs-body-sm`（15）：要点说明、名字
- `--fs-sm`（14）：界面文字
- `--fs-xs`（12.5）：注释
- `--fs-eyebrow`（12，中文 13）：小标签
- `--fs-figure`（36–44）：价格卡和计算器里的大数字

手机、小窗口、演示导览这些 mock 照 App 的界面尺寸来，不受上面这张表约束，但不小于 11px。

**小标签只有一种：`.eyebrow`。** 英文用等宽大写，中文用无衬线、不大写。价格卡标签、章节头的"编号 / 名称"、工牌上的职位都用它。

**章节头（`.shead`）。**
- 一列、同一条左边线：细线 → 编号 / 名称 → 两段式标题 → 说明。说明紧跟在标题下面，不另起一栏。
- 只用三种颜色：正文色（标题前半句）、次要色（后半句、名称、说明）、品牌色（编号）。

**字重。** 只用 400 / 500 / 600 三档；`b`、`strong` 也是 600。

### 舞台卡与滚动动效

宣传口径以桌面为主。下面的滚动联动只在宽屏（≥1024px）、有鼠标、没开"减少动态效果"时启用。窄屏和无 JS 时页面停在终态，内容完整可读。动效参考了 bevel.health，但没有引第三方库。

**动效的硬规矩：每个动画都要说得出它在告诉用户什么。**
- 能动的只有这几类：内容的出现 / 切换；对操作的反馈（悬停、按下、点击）；真实在进行的过程（打字、生成、数据从哪流到哪）；机器人的状态和情绪。
- **严禁背景 / 装饰层的动画**——背景、光晕、边框、纹理一律静止。具体不许做：
  - 背景里自己循环播放的光圈 / 光框扩散（"隧道"、涟漪、雷达波）；
  - 呼吸、脉动的光晕；
  - 沿边框巡游的扫光；
  - 漂浮的光斑、粒子；
  - 跟随指针的点阵、聚光灯。
- **唯一的例外**：Hero 顶部的天空（用户 2026-10-31 明确要求）——深色：约五分之一的星星慢慢明暗闪烁（3–7 秒一周期、各自错开），两颗流星隔十几、二十秒才划过一次、每次不到一秒；浅色：三朵白云极慢地从左往右飘（横穿一次 3–5 分钟），约六成四角形细小闪光偶尔亮起、转一下再隐去；"减少动态效果"时全部静止。保持"极其简单"，不要加量、不要扩展到别处。
- **第二个例外**：首页第 4 节章节头两侧的厂商图标砖（用户 2026-10-31 明确要求"logo 有微弱的浮动效果"）——每块砖上下浮动 ±3px，周期 6–10 秒、起点各不相同；"减少动态效果"时静止。不要加大幅度，也不要套到别的图标上。
- **第三个例外**：Hero 背景里的模型厂商标志（`components/HeroLogos.astro` + `styles/hero-logos.css`，用户 2026-10-31 明确要求"logo 做微弱浮动、尽量淡化"）——标题两侧各五枚单色标志，最清楚的一枚是正文色的 12%（浅色 11%；压到 7% 时用户说看不到，更早的版本又嫌明显），远的更小更淡、略虚；各自轻轻漂（上下 8px、左右 3px、转 ±1.5°），5–8.5 秒一个来回、起点错开；只在文字两侧的空白里，不压标题、按钮和舞台；中等宽度只留外侧几枚，窄屏不放；"减少动态效果"时静止。不要加量、不要加颜色、不要扩展到 Hero 以外。
- 说不出含义、只是"让画面动起来"的效果，一律不加。App 端同一条规矩，见 `ui/design/README.md` 的「动效」。

**舞台卡（`.stage`）。** 视觉母版是"认识机器人"那张 `.crew`：深底、一圈细线、32px 圆角，底光用这一块主角机器人的颜色。
- 颜色写在标签的 `--stage-glow` 上：动手橙、记忆绿、模型紫、数据去向绿。
- UI 强调色仍是品牌黄绿。

**滚动联动（`scripts/scroll-fx.ts`）。**
- 原理：`[data-fx]` 元素随滚动拿到 `--p`（0 → 1），样式只写在 `html.fx` 下，用 `calc()` 把 `--p` 换成位移、缩放或倾斜。
- `.fx-rise`：舞台卡升起来。
- `.fx-float` + `data-fx="through"`：视差，偏移量由 `--depth` 控制。
- `data-fx-prev`：叠卡时把进度写给前一张卡。
- 跑马灯离开视口就暂停。

**各块用到的效果。**
- **Hero**（`sections/Hero.astro`，样式在 `home.css` 的"1 Hero"）：
  - 四周留 8px 的圆角大卡片（手机 6px）。背景要克制、除顶部天空外全部静止，颜色只有很弱的变化（舞台换机器人时跟着微微变色，`--hero-hue` / `--hz-glow`），不用品牌黄绿、不加装饰图形：底色渐变（深色下顶上偏一点点夜空蓝）→ 一层很淡的中性顶光（顶上 160px 淡入，不在卡片顶边切出亮带）+ 顶部的天空（`Hero.astro` 里伪随机生成，标题背后稀一些，往下渐隐）：深色是星空——约 340 颗冷白小星（少数偏蓝 / 偏暖，几颗亮星带一圈光），约五分之一慢慢闪，偶尔划过一颗流星；浅色是晴空——顶上一片清透的浅天蓝（往下渐淡，到说明文字附近回到卡片的白；这是浅色"只用中性白灰"的例外，用户 2026-11-01 要的）+ 三朵很软的白云（纯 CSS，底下压一层极淡的中性灰影子，极慢地飘）+ 四十来个四角形的细小闪光（颜色跟着当前机器人的色调），约六成偶尔亮起、转一下再隐去，不放流星（见上面的例外）→ 舞台后面一层极淡的机器人色 → 一道巨大的弧形地平线托住窗口（整圈一线淡亮边、正中稍亮），上方一层很淡的光晕 → App 同款磨砂颗粒。不画线框、网格、点阵、放射光束。
  - 舞台的遮罩只负责把底边淡进地面；遮罩会裁掉盒子外的一切，所以 `.hstage` 往上多留了 `--bleed`（220px），窗口四周的光晕不会在舞台顶边被切平。倾斜的滚动进度挂在 `.hstage__devices` 上。
  - 文字居中一列：小胶囊（六个角色头像 + 一句话，链到"认识你的机器人"）→ 标题 → 一句说明（两行以内）→ 下载 / 演示 → 三条要点（每条前面一个勾，颜色跟着当前机器人）。
  - 标题在 Hero 里放大一档（英 46–88、中 42–84）。中文逐字、英文逐词由虚变实升起；第一行是渐隐的渐变字，行尾蹲着会看指针、能戳的天天；关键词深色下是黄绿渐变字，浅色下改用当前机器人的颜色（深一档，跟着换幕渐变；黄绿在浅底上发脏），底下垫一团同色的光，字出齐后一道亮光从左到右扫过。不铺荧光底、不加下划线。
  - 间距只取 4px 尺度：胶囊 → 标题 24、标题 → 说明 24、说明 → 按钮 32、按钮 → 要点 24（手机 16 / 16 / 24 / 16）。
  - 舞台是一台照 App 原生界面（`ui/design`、`ui/css/shell.css`、`chat.css`）做的窗口：环境光 + 毛玻璃侧栏（红绿灯、搜索、机器人行、账户）+ 浮起的主面板（顶栏、气泡、"思考中 → 用时"、代码块、审批卡、文件卡）+ 玻璃输入框（权限、模型、发送）。App 的语义 token 抄在 `.hstage` 的 `--a-*` 上，深浅两套，字体也用 App 的系统字体。
  - 循环 18 秒三幕，每幕换一个机器人：天天聊天改代码 → 飞飞动手整理文件（要你批准）→ 芽芽回聊天软件里来的消息（右下角的手机同步）。侧栏选中行、顶栏、对话、输入框里的模型和窗口环境光（`--aura-hue`）跟着切换；机器人干活时侧栏亮绿点、发送钮变成停止。时间线和演示导览同一套（`scripts/tour.ts`：`data-steps` 切幕，`data-at` / `data-type` 出消息）。窗口往后仰，随滚动摆正。
  - 宽屏（≥1280px）两侧有流动卡片：左边的模型、任务、消息流进窗口，右边的结果、文件、记忆从窗口后面流出来（`data-flow` 写进度 `--k`）。
  - 按钮：指针移上去从底下升起一团高光，演示按钮再放大一点；下载按钮底下垫一层品牌色的光。
  - 文案求短：舞台里的字尽量复用演示导览、"能动手"、角色的文案，新增的在 `hero.stage`。
  - 入场（纯 CSS）：地平线升起、光晕亮起 → 胶囊 → 标题一块块出来 → 天天弹出 → 说明、按钮、要点 → 窗口、手机升上来 → 两侧卡片淡入 → 关键词扫光。减少动态效果时舞台停在完成态（第三幕）、不放流动卡片；窄屏只留主面板。
- **章节头**：第一次进视口时细线从左画出，编号、标题、说明依次升起。
- **认识机器人**：样式不变，只随滚动升起来。
- **第 3–8 节的通用规矩**：版式照第 2 节——章节头 + 一张主持机器人底光的舞台卡；叙事照 bevel.health——短标题 + 一句话，然后一块会动的大示意。品牌黄绿只给主操作（下载、获取 Key），其余强调用机器人的颜色、压得很淡。
- **能动手 / 会记住**（`scripts/sections.ts` 的 story）：
  - 桌面（≥1024、高 ≥700）：左边两章各占大半屏依次滚过，当前那章亮、另一章淡；右边舞台卡吸顶换场（旧幕往上退、糊掉，新幕升上来），底光从飞飞的橙渐变到芽芽的绿；卡顶两个小标签能点。
  - 窄屏 / 无 JS：舞台卡拆开，每章文字下面跟着它自己的场景卡。
- **模型**（orbit）：两圈压扁的椭圆轨道像行星环，外圈模型、内圈厂商反向慢转，转到前面的变大变亮、压在机器人前面（`sin()` / `cos()` + 注册过的 `--orb` 角度）；当前在用的模型在环上亮起，点环上的模型就换它来答。舞台卡随滚动升起来；跑马灯离开视口就停。手机上只留对话演示。
  - **厂商标志**：外环模型、内环厂商、跑马灯、模型选择器的胶囊和分组标题前面都带厂商标志——用官方彩色版（`VendorSprite color`；OpenAI、Anthropic、xAI、Moonshot、TypeSafe 本来就是单色标志，跟着文字颜色走）。这一节只放有标志的厂商，不放快手（用户 2026-10-31 要求；完整的模型与价格在 /pricing）。标志取自 LobeHub Icons（`@lobehub/icons-static-svg`，MIT），生成在 `src/data/vendor-logos.ts`（`VENDOR_LOGOS` 单色、`VENDOR_LOGOS_COLOR` 彩色），整页只放一份图标表（`components/VendorSprite.astro`），各处用 `components/VendorLogo.astro` 引用；没有标志的厂商（比如"快手"）在别处显示首字母小圆片，第 4 节里不出现。各标志是其所有者的商标，只用来标明模型出自哪家；来源写在 /licenses。价格快照里出现新厂商时，在 `scripts/vendor-logos.ts` 的 `FILES` 里加一行再重跑（用法见脚本开头）。
- **数据去向**："你的设备"是一圈静止的淡绿边框；动的只有表示数据流向的两样——会走的虚线和走出边界的那颗小光点。
- **多端**（hub）：竖排 tabs（↑ ↓ / Home / End）；换入口时示意小图里的东西依次动起来，天天看过去、蹦一下。窄屏上清单变成一行可横滑的胶囊。
- **常见问题**：打开的那条铺成卡片，回答平滑展开（支持 `::details-content` 的浏览器）。
- **收尾横幅**：背景静止（顶光、星空、地平线都不动，只用中性色，全卡只有下载按钮是品牌色）；卡片跟着页面主题走，不要写死 `data-theme="dark"`（浅色下会变成白卡白字）；百叶窗从下往上拉开，底边的机器人跟着依次升上来。

## 部署（本机 Docker）

```bash
cp deploy/.env.example deploy/.env      # 填域名、仓库地址、安全邮箱；统计和镜像名可选
docker compose -f deploy/compose.yml --env-file deploy/.env up -d --build
```

- `builder` 容器：启动时构建一次，之后每天 04:00（UTC+8）重新抓价格、重新构建；每次输出到共享卷的新目录，成功后原子切换 `current` 软链接，失败就继续用上一版（保留最近 3 版）。
- `web` 容器：nginx 只在 `127.0.0.1:${SITE_PORT:-18490}` 提供静态文件。
- 域名与证书走宿主机的 Caddy，分两步：
  1. 先放只有 HTTP 的站点（`deploy/anymodelbot.Caddyfile.example`），带 `/.well-known/acme-challenge/` 给 certbot 验证用。宿主机 Caddy 关了自动 HTTPS（`auto_https off`）时，这一步不能引用还不存在的证书文件，否则整份 Caddy 配置校验失败，共用这个 Caddy 的其他站点也受影响。
  2. 域名解析到本机后，用 certbot（webroot）签证书，换成 HTTPS 站点（HTTP 跳 HTTPS、www 跳主域名），校验整份配置、确认已有站点一个不少再 reload，并装上每天的续期任务（续期后 `caddy reload --force` 才会重新读取证书文件）。
- 下载数据不用手填：每次构建读 `GITHUB_URL` 的最新 Release，生成版本、发布日期、各平台下载地址（直达 GitHub）、SHA-256（取 Release 里的 `SHA256SUMS`）和大小；官网服务器不提供安装包下载。读取失败时这次不构建、继续用上一版；最新 Release 缺哪个平台，生产构建就会失败并提示。
- 部署值没填齐时可以先用 `SITE_BUILD=draft` 跑起来（页面上会留着 `{…}` 占位符）。

## 数据从哪来

- **价格**：构建时请求 `https://modelflare.dev/api/pricing`，用 `src/lib/pricing.ts` 算出默认线路价、分档、条件价线路和官方价（规则与 modelflare.dev/pricing 前端一致：有 `official_input_price` 用它，否则用基础价），写入 `src/data/pricing.snapshot.json`。抓取失败或数据异常时沿用快照，页面显示快照日期。
- **机器人**：`scripts/sync-from-app.ts` 从 `../ui/design/bots/*.webp` 复制精灵图、从 `../THIRD_PARTY_NOTICES.md` 同步许可（Docker 构建上下文里没有应用目录，用已提交的副本）；几何（`src/lib/bots.ts`）与 `../ui/components/avatar.js` 的 `BOT_CHARS` 不一致时会警告。头像样式 `src/styles/bots.css` 移植自 `../ui/design/components/avatar.css`。
  - 精灵图另有同分辨率的 AVIF 版（`public/bots/*.avif`，约为 WebP 的一半），支持的浏览器经 `image-set()` 优先用它，其他照旧用 WebP。AVIF 必须从原图编码（`npm run bots:avif`：重跑 `../scripts/build-bot-avatars.py --png` 拿无损精灵图，q58 的画质按 PSNR 不低于 WebP q86），不能拿 WebP 再转。生成时把对应 WebP 的哈希记在 `src/data/bots-avif.json`；WebP 更新了而 AVIF 没重做，`check-images` 会失败。
- **演示**：Hero 的"看演示"和"它能动手"都是动画（`src/components/DemoTour.astro`、`src/scripts/tour.ts`），不依赖视频文件。"看演示"点开就自动轮播、播完从头循环，没有播放 / 暂停 / 翻页按钮，底部进度条可点跳步。
- **文案**：`src/i18n/zh.ts`（源语言）与 `en.ts`，页面里不写死文案。例外是两种语言内容本来就不同的：聊天渠道（`src/data/channels.ts`）和公告（`src/data/announcements.ts`），各写各的，禁词扫描同样覆盖 `src/data`。
