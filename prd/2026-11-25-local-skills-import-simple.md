# 从本机快速导入技能并使用

**状态：** 正式 PRD · 已定稿

**定稿时间：** 2026-11-25 01:29（上海时间）

> **阅读说明**：线稿是需求的一部分，请逐张打开图片地址并结合相邻文字理解。线稿为原创灰阶交互示意，不是实机截图；图文冲突以文字为准。

## 一、业务背景与目标

用户电脑中已经安装了其他工具的技能，希望少做手工查找、打包和逐个安装，尽快交给机器人使用。

**目标**：找到技能 → 选择并预览 → 一次导入 → 在当前机器人上使用。正常流程不要求处理版本、分配多个机器人或配置后台任务。

## 二、产品逻辑与范围

- **统一存放、按机器人使用**：技能进入同一安装实例的本机「我的技能库」，机器人只保存使用关系和开关；可有运行部署副本，不产生各机器人独立编辑的内容源。不是账号云同步，不跨机器合库。
- **复制，不搬走**：导入是一次内容复制，不改来源、不持续同步；入库与开启分别报告。兼容检查通过不等于运行必然成功。
- **一次只选一个使用目标**：从机器人进入，默认勾选「导入后在当前机器人上使用」；从库进入，默认只入库。其他机器人以后在自己的设置中按需开启，不做导入时的多机器人分配。
- **只增加必要入口**：「我的技能库」提供「从本机导入…」；机器人设置的技能页提供同一入口和「从技能库添加…」。公开技能目录、原ZIP／GitHub／对话安装及「我存的」入口不改名、不重做操作流程。
- 新文案中文、英文及其他已支持语言同版同步。界面复用现有灰色组件，不增加管理控制台。

**本期不做**：记忆迁移、机器人分发、云同步、整库导出、自动职责推荐、批量多机器人分配、来源自动同步、导入时替换已有条目、新增共享更新／版本回退管理页、新增定时资格或暂停恢复流程、插件整包迁移、自动安装依赖。

## 三、需求详情

### R1 发现与选择：只找明确位置

- 打开「从本机导入…」后，显示实际来源机器；只枚举下表自动根内的目录项及`SKILL.md`文件名，展示候选数量和相对位置。初始不勾选；可多选或全选，点「下一步」才读取所选完整技能目录作本地预览。未选项不读正文。
- 「选择文件夹…」接受一个技能文件夹、包含多项技能的根，或一个具体项目。项目只检查表内已知相对位置，不递归搜索所有仓库、项目父目录、Home或磁盘。选到Home、磁盘根或应用数据总根时不递归，提示选择具体技能根或项目。技能根内允许分类子目录；遇到技能定义即划定该项边界，不把其资源里的示例定义自动拆成新技能。
- 自动发现只在客户端与库宿主同机、具备原生文件访问能力的桌面端开放。网页／远端显示不可用原因，可继续使用原ZIP／GitHub方式；不把浏览器电脑路径当远端宿主路径，不扫描另一台机器。
- `~`是来源机器实际用户主目录；macOS／Linux用系统主目录，Windows用`%USERPROFILE%`。不读取shell配置或整份环境猜自定义根；环境变量、多配置、插件内独立技能和其他位置一律手选，不自动扫插件缓存或管理员目录。

### R2 预览并一次导入

- 预览列出名称、简短描述、来源位置、可导入／已存在／冲突／不兼容状态；「查看」展开所选项的相对文件和原因，不新开复杂检查页。有脚本显示「含脚本，导入不会执行」。不把文件内容或私人绝对路径交给模型分析、修复或写日志。
- 每项须有一个可解析的UTF-8 `SKILL.md`及非空正文，原调用名为小写字母／数字与单连字符、最长64字符；展示标题可取原标题或目录名，不改调用名，描述非空且最长1024字符；只在副本移除BOM。能从目录名／首标题明确补全的名称／描述标明补全值，最后确认一并接受，补全后仍须通过同一格式校验；其余缺失或不安全YAML显示原因，不猜正文或改自引用。
- 一个根中多项技能逐项处理；定义边界不清、资源依赖根外插件、缺必需资源时跳过该项，不假称整包可用。保留原手动调用、禁止自动调用及其他限制语义，包括`disable-model-invocation`、`user-invocable`、`allow_implicit_invocation`；当前运行环境无法等价保持的策略、hooks或权限语义不允许导入／开启，不静默变成自动调用，未知限制性字段不能当作展示字段忽略。
- 不自动移植专属工具、替换平台路径变量、下载资源、执行脚本或安装依赖。已知缺必需依赖的项不能开启；无法静态核实的说明「依赖尚未验证」，不承诺可运行，也不新增试跑流程。
- **相同内容**：比较完整相对路径及文件字节，定义、策略、脚本和资源都参与；不只比名称或正文。外层路径、平台标签、`.git`、`__MACOSX`、`.DS_Store`及`._`资源分支不计，忽略项须可查看。同内容多处来源合为一个候选；库中唯一匹配则复用，不重复入库、不自动打开已关闭关系。历史多身份不强合并，提示已存在并从库中选择使用。
- **同名不同内容**：默认「跳过」，可选择「另存一份」；本期无替换。另存使用独立条目和展示名后缀区分，原调用名与正文不改；同批冲突也先展示最终动作。不能用给调用名自动加后缀伪装兼容。
- 最后只显示所选合格项、动作和「导入后在{当前机器人}上使用」一个勾选项。机器人入口对新条目默认勾选；库入口不勾选，允许只入库。已有条目保持原使用状态，需要新增使用时在机器人设置操作。点「确认导入」提交；取消预览不改来源或库；没有合格新增项时确认置灰，已有内容可回到库中查看和使用。

### R3 使用与结果：只操作当前机器人

- 完成后在原界面汇总「已入库{added}项，已在{bot}上开启{enabled}项，跳过{skipped}项，失败{failed}项」，失败项就近显示原因；仅入库隐藏开启统计，不显示空机器人目标。可关闭结果，不增加恢复控制台或要求配置定时。
- 「我的技能库」仅提供名称／描述搜索、从本机导入、查看技能及当前使用机器人列表；保留「我存的」来源标记。空库提示导入或在对话中保存，无搜索结果不说库为空。不增加来源筛选器、版本栏或更新／回退按钮。
- 机器人设置「技能」中用「从技能库添加…」选择条目，只应用到当前机器人；已有关系不重复添加。关闭只影响该机器人，库内容及其他机器人不变；删机器人不删库。
- 同一机器人同调用名只开一份；冲突时不自动关闭旧项，提示先关闭该机器人的同名项再开启。不同机器人可以使用不同条目。在库中暂存的另一份不影响任何已启用技能。
- 开启结果区分已开启／等待空闲生效／生效失败；沿本来使用节奏在后续消息生效，不打断当前任务，不用旧部署假报成功。失败只重试开启，不重复入库。
- 对本次导入的新条目，库中未被任何机器人开启且无运行任务占用时，可在「⋯」选择「从库移除」，确认仅移除本机库副本并清理已关闭的引用；使用中提示先关闭。存在原有受保护关联的条目不走此轻量移除，保留原管理入口的删除保护。原技能已有的编辑、删除及单技能导出仍在原入口保留，不在本次导入中扩建管理功能。

### R4 必要异常与安全

- 每项完整写入后才发布，允许部分成功；开启失败保留入库内容。相同请求查询原结果，未知时显示「正在确认导入结果」，不允许重复提交；明确失败后只重试失败项／阶段。取消停止未开始项，已成功项保留，提交中的项先核对结果，不假装整批回滚。
- 预览后源内容变化／消失、目标被删、使用关系变化或同名条目并发新增，重新校验该项，必要时返回预览；不以旧确认覆盖、不改用另一机器人／机器。切界面不改变原目标，结果仍归原操作。
- 每技能实际内容最多64MiB、2000条目，定义最多256KiB；读取按实际字节与条目有界处理，超过时阻止该项，扫描中止要标不完整。只接受确认根内普通文件，拒绝路径逃逸、设备／特殊文件和规范化后的路径碰撞；不执行HTML／脚本，不把嵌套压缩包自动展开。ZIP／GitHub的原传输与安全限制不因本机入口放宽。
- `.env`、`id_rsa`、`credentials.json`、`memory.md`等疑似私人文件名先阻止该项，不读其正文，提示自行整理后重选；不静默删资源，不保证识别所有秘密。私人路径和技能内容不发模型自动处理；使用时仍受机器人现有文件、工具权限和批准约束。

### R5 最小底座与旧能力兼容

- 本机新导入直接写统一库。原ZIP、GitHub、对话安装、对话保存通过最小读写适配接入同一条目索引；保留原入口和确认方式，不要求用户重新导入。原「我存的」在库中带来源标记，不另造一套内容。
- 旧内容允许原地保留物理布局，渐进登记稳定条目与机器人关系，不强制启动时搬迁全部文件、合并同内容身份或重写历史。登记前后名称、完整内容、原开关及关联身份不变；中断重试不重复，失败保留原数据与现有使用，仅本次导入／登记写入失败。未登记不能当作不存在而重复导入。
- 原有编辑、更新、回退及导出能力不删除。条目被多个机器人引用后，原入口修改内容须说明影响的使用机器人并统一发布完整内容；当前任务保留原内容，新任务用完整生效内容，失败不发布半包。本期不增加外部导入替换、共享版本管理或全量历史迁移；不能保留两个可独立写入的权威副本。
- 旧「我存的」验证、使用关系及原定时关联保持；纯登记不改原规则开关、下次时间、预算或权限，不补跑、不暂停／恢复。实际内容或使用关系被修改时仍保留原安全校验；新导入不因同名、外部元数据或复用副本获得可信验证或新增定时资格，不新增定时操作界面。
- 不新增全库额度或跨来源合并配额。本机技能关联到机器人时，使用原普通导入类型的容量检查；只入库不占机器人使用名额。既有来源的容量与计数口径保持，旧超限数据不裁剪、不自动关闭；满额仅报告本次新增使用失败，不影响库中已成功内容、关闭、查看和现有使用。

**验收**：旧入口安装／保存后能在同一库看到；旧内容、开关及原关联不变，登记重试不重复、不双写。原有编辑／导出继续可用，共享修改不只更新某个部署副本；纯登记不触发原规则变化，外部包不能伪造可信身份。满额不删旧内容，复用不多占额度。

## 四、技术前提

1. 同一条目内容与机器人使用关系可区分；兼容索引覆盖旧入口，新入口不依赖全量物理迁移。登记、读取和修改不能形成两套互相独立的内容源。
2. 来源机器和原生授权真实可验证；路径、内容、兼容策略、并发与容量在服务侧校验。单项提交和部署完整可核对，失败或半包不进入可调用状态。

## 五、实现决策记录（2026-11-25，基于 v0.1.47）

实现时对照现有代码定下的做法，理由一并写在这里：

1. **存放**：新条目在数据目录 `skill-library/`（`index.json` + 按内容摘要命名的 `packages/`），机器人只记 `uses[机器人] = { on }`。旧的各机器人技能（`skills/<机器人>/`）和「我存的」（`my-skills/`）原地不动，由 `UserSkills.libraryView` 以 `bot:<机器人>:<名字>`、`mine:<名字>` 两种稳定 id 合进同一份索引。理由：R5 要求不强制搬迁、未登记不能当作不存在；稳定 id 由旧身份推出，重试不会重复登记。
2. **渐进登记的时机**：旧的各机器人技能只在两种情况下复制进库——在别的机器人上「从技能库添加…」它，或它所在的机器人被删除（落实「删机器人不删库」）。登记沿用原 id、名称、内容、来源和开关，先写库再去掉旧记录；中途断了，下次读库时按 `legacy` 记录收尾。「我存的」不搬，加到别的机器人走它原来的开关。
3. **原入口改库条目**：ZIP、GitHub、对话安装装同名技能时，如果这个机器人用着同名的库条目，就替换库里那一份（确认页和卡片说明「此技能也在{bots}中使用」），所有用它的机器人空闲后一起换上完整新内容，开关不变。没有用着的库条目时行为和以前一样。
4. **「另存一份」的显示名**：在原标题后加「 (2)」「 (3)」……，各语言一致；调用名和正文不改。
5. **限制字段**：DSH 只认 `disable-model-invocation`、`user-invocable`，照原样保留；`allow_implicit_invocation: false`（frontmatter、`policy` 或 Codex 的 `agents/openai.yaml`）等价写成 `disable-model-invocation: true`，在确认页作为补全值说明。`allowed-tools`、`hooks`、`context`、`agent`、`model`、`permissions` 等无法等价保持的字段整项不导入；名字像限制（含 allow、deny、permission、policy、hook、tool、require 等）的未知字段同样不导入，其余未知字段当展示字段，在「查看」里列出。`allowed-tools` 在不同版本里既有「免批准」又有「只允许」两种含义，不能确定是否扩大权限，按 R2 归为不兼容。
6. **依赖**：有脚本、依赖清单（`requirements*.txt`、`package.json`、`pyproject.toml` 等）、`compatibility` 字段或 Codex 声明了 `dependencies` 的标「依赖尚未验证」，可以导入和开启。用到平台路径变量（`${CLAUDE_…}`、`${CODEX_…}` 等）、Markdown 链接指向技能目录外或指向不存在的文件，视为已知缺必需依赖，整项不导入。
7. **容量**：开启库条目时按「这个机器人已装的 + 开着的库条目」不超过 100 计；关着的关系和只入库都不占名额；原 ZIP / GitHub 的计数口径不变。
8. **「从库移除」**：只给存在库里的条目（本机导入的、登记进库的），没有机器人开着、也没有运行中的进程还部署着它时可用。登记进库的旧技能原来的「删除」入口在机器人设置里已换成库条目的开关，所以同样允许轻量移除；「我存的」仍走原来的「管理」和删除保护。
9. **「我存的」的可信验证**：回合成功后只给在这个机器人上打开的那一份「我存的」去掉「未验证」，同名的导入技能用成功不算，外部包不能借名字获得验证或定时资格。
10. **桌面端判定**：要有桌面外壳（`app.desktop`）且请求来自本机回环地址才开放查找；「选择文件夹…」用系统选择器，显示隐藏目录，路径只在服务端保存，界面只拿到随机的候选 key。
11. **入口**：「我的技能库」是独立页面（`#/skills/library`），从头像菜单和命令面板进入；机器人设置 › 技能新增一行「我的技能库」，放「从本机导入…」「从技能库添加…」。从库进入时确认页显示上次打开的机器人、默认不勾选。
